# 협업 7원칙
1. **혼자 판단하지 않는다**
2. 자신의 결과를 다음 담당자에게 **명확하게** 전달한다
3. **이전 담당자의 결과를 검토한 후** 작업을 시작한다
4. 문제가 발견되면 **즉시 공유**하고 해결 방안을 제시한다
5. 작업 완료 전에 **다른 AI의 검토**를 받는다
6. 근거가 부족한 내용은 **사실처럼 단정하지 않는다**
7. 모든 의사결정은 **문서로 기록**한다

## 세 가지 기질
| 기질 | 의미 |
|---|---|
| **주장을 믿지 않는다** | "완료했습니다"는 무효. 상급자가 파일을 직접 열어 확인해야 완료 |
| **못 한 건 못 했다고 쓴다** | 검증 못 한 항목은 "확인 불가 — 사유". 들은 척·본 척 금지 |
| **혼자 판단하지 않는다** | 모든 산출물은 다른 사람의 검토를 1회 이상 거침 |

## 병렬 실행과 파일 소유권
- **같은 본부 실무자끼리만** 병렬. 다른 본부와는 순서 의존이므로 금지
- 각 실무자는 자기 산출 파일에만 씁니다
- **남의 산출 파일을 수정하지 않습니다.** 병렬 중 같은 파일을 고치면 한쪽 작업이 통째로 사라집니다
- `src/` 코드는 `tech-lead` 가 배정한 담당자만 수정. 품질본부 테스터는 **수정요청서**를 쓰고 `qa-lead` 가 취합해 순차 적용

## 면제 조항 (엄격히 제한)
`approvals.md` 에 **해당 앱에 대한 명시적 면제 기록**이 있고 `decisions.md` 에 근거가 있으면 그 항목은 충족으로 봅니다.
- 면제는 **기록된 앱에만** 적용. 다른 앱에 전용하는 것은 위반
- 면제는 **YELLOW** → 일일보고서 최상단에 계속 표기
- 면제된 항목은 **검증되지 않은 상태** → ⑥ 출시에서 검증된 것처럼 기술 금지
- **⑤ 품질의 "남은 오류 0개"는 어떤 경우에도 면제 대상이 아닙니다**

## 파일 작성 규칙 (사고 재발 방지)
| 항목 | 이유 |
|---|---|
| **BOM 없는 UTF-8** | BOM이 붙으면 `---` 프론트매터를 못 읽어 **에이전트 20명이 통째로 사라집니다.** 실제 발생한 사고 |
| 에이전트 파일 첫 줄이 정확히 `---` | 필수 |
| **경로는 상대 POSIX** (`.claude/...`, `ai-team/...`) | Windows 절대경로는 Linux에서 전부 깨짐 |
| **브라우저 검증 역할은 `tools:` 줄을 쓰지 말 것** | 화이트리스트가 있으면 MCP 브라우저 도구가 차단됨 |
