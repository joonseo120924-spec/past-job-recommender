# 📜 팀 규정 (정본)

> 출처: 노션 「📜 팀 규정 · 마스터 판단 기준」 (2026-08-09 복원)
> **무엇과 충돌하든 이 문서가 우선합니다.**

## 협업 7원칙

1. **혼자 판단하지 않는다**
2. 자신의 결과를 다음 담당자에게 **명확하게** 전달한다
3. **이전 담당자의 결과를 검토한 후** 작업을 시작한다
4. 문제가 발견되면 **즉시 공유**하고 해결 방안을 제시한다
5. 작업 완료 전에 **다른 AI의 검토**를 받는다
6. 근거가 부족한 내용은 **사실처럼 단정하지 않는다**
7. 모든 의사결정은 **문서로 기록**한다

## 상호 검토 — 7항목

모든 결과물은 최소 1회 검토를 거칩니다.
검토 항목: 누락된 내용 · 논리적 오류 · 사용자 경험 · 성능 · 보안 · 유지보수성 · 일관성

| 산출물 | 작성 | 검토 |
| --- | --- | --- |
| 아이디어 | `strategy-lead` | `product-planner` |
| 기획·설계 | `product-planner` | `tech-lead` |
| 디자인 | `design-lead` | `frontend-dev` |
| 코드 | `tech-lead` | `qa-lead` |
| 테스트 결과 | `qa-lead` | `tech-lead` |
| 스토어 자료 | `gtm-lead` | `product-planner` |

**검토자는 이미 단계를 마쳤거나 다음 단계에서 그 산출물을 실제로 받는 사람**이어야 합니다.
아직 작업을 시작하지 않은 사람을 검토자로 기록하는 것은 규정 위반입니다.

## 의견 충돌 해결

① 각자 근거 제시 → ② 장단점 비교 → ③ **사용자 가치** 우선 → ④ **보안·안정성** 우선 → ⑤ `decisions.md` 기록

## 병렬 실행과 파일 소유권

- **같은 본부 실무자끼리만** 병렬. 다른 본부와는 순서 의존이므로 금지
- 각 실무자는 자기 산출 파일에만 씁니다
- **남의 산출 파일을 수정하지 않는다.** 병렬 중 같은 파일을 고치면 한쪽 작업이 통째로 사라집니다
- `src/` 코드는 `tech-lead` 가 배정한 담당자만 수정. 품질본부 테스터는 **수정요청서**를 쓰고 `qa-lead` 가 취합해 순차 적용

## 인수인계 경로 (통일)

파트장만 작성합니다. 실무자는 쓰지 않습니다.

```
<앱폴더>/handoff/
  01-전략.md      strategy-lead
  02-기획.md      product-planner
  03-디자인.md    design-lead
  04-개발.md      tech-lead
  05-QA.md        qa-lead
  06-출시운영.md  gtm-lead
```

`ai-team/handoff/` 는 **폐기된 경로**입니다. 사용하지 않습니다.

## 면제 조항 (엄격히 제한)

`approvals.md` 에 **해당 앱에 대한 명시적 면제 기록**이 있고 `decisions.md` 에 근거가 있으면 그 항목은 충족으로 봅니다.

- 면제는 **기록된 앱에만** 적용. 다른 앱에 전용하는 것은 위반
- 면제는 **YELLOW** → 일일보고서 최상단에 계속 표기
- 면제된 항목은 **검증되지 않은 상태** → ⑥ 출시에서 검증된 것처럼 기술 금지
- **⑤ 품질의 "남은 오류 0개"는 어떤 경우에도 면제 대상이 아닙니다**
