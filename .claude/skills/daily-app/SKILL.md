# 일일 사이클

## 0. 어제까지의 상태를 먼저 읽는다
1. **노션** 「📓 작업 일지」 (`3b750286-df80-8173-a09e-f8dc7712e713`) — 어제 항목의 **"내일 이어받을 지점"**
2. **저장소** 정본 4개 — `.claude/team-rules.md`(최우선) · `.claude/team-org.md` · `.claude/master-doctrine.md` · `ai-team/SESSION-LOG.md`
3. `ai-team/cycle.md` · `board.md` · `approvals.md`

노션 도구가 이 실행에 없으면 **저장소 파일만으로 진행**합니다. 저장소가 실제 상태이고 노션은 기록입니다.
어긋나면 저장소를 기준으로 삼고, 어긋난 사실을 보고서에 적습니다.

## 1. 오늘이 며칠차인지 판정
| 일차 | 오늘 할 일 |
|---|---|
| 1일차 | ① 전략 → ② 프로덕트 |
| 2일차 | ③ 디자인 → ④ 개발 |
| 3일차 | ⑤ 품질 (오류 0개까지) |
| 4일차 | ⑥ 출시운영 → 최종 보고서 |

5일차 = 다음 앱 1일차. 4일 안에 못 끝내면 **미완인 채로 종료하고 사유를 기록**합니다.

## 2. 사용자가 없다는 전제로 진행
`master-doctrine.md` 의 GREEN/YELLOW/RED 로 판단합니다. **멈춰서 대기하지 않습니다.**
RED에 막히면 그 단계만 "차단됨"으로 기록하고 나머지를 진행합니다.

## 3. 일일보고서
`ai-team/apps/<날짜>/docs/일일보고서-<날짜>.md`

```markdown
# 일일보고서 <날짜> — 사이클 N · M일차

## 🟡 YELLOW (있으면 최상단)
## 오늘 한 일
## 승인 / 반려
## 남은 오류
## 감사관 판정
## 커밋
## 내일 이어받을 지점
```

**면제(YELLOW) 항목은 매일 보고서 최상단에 계속 표기합니다.** 사라지면 안 됩니다.

## 4. 마감 — 저장소 (생략 불가)
`board.md` · `cycle.md` · `SESSION-LOG.md` 갱신 → **커밋 + 푸시**.
원격 컨테이너는 커밋하지 않으면 전부 소멸합니다.

### 4-1. `ai-team/STATE.md` 를 다시 쓴다 (생략 불가)
**한 장짜리 현재 상태**입니다. Windows 로컬에서 Claude Code 를 열면 이 파일이 세션 시작 시 자동으로 읽히고(`.claude/settings.json` 의 `SessionStart` 훅), `team-sync.ps1` 도 이것을 출력합니다. **갱신하지 않으면 다른 기기가 어제 상태를 오늘 상태로 착각합니다.**

매일 다시 쓸 값: 최종 갱신 시각 · 사이클/일차 · 다음 단계 · YELLOW 목록 · 막힌 것 · 본부별 표 · 노션 미동기화 건수.
기존 형식을 유지하고 값만 바꿉니다. 배경은 `ai-team/local-windows.md`.

## 5. 마감 — 노션 정리 (생략 불가)
절차 정본: **`ai-team/notion-sync.md`**

요약하면 —
1. 오늘 항목을 `ai-team/notion-queue/<날짜>.md` 에 **먼저 씁니다.** (노션 도구 유무와 무관하게 항상)
2. 노션 도구가 **있으면** 큐에 밀린 항목을 오래된 것부터 「📓 작업 일지」에 append 하고, 큐 파일 상단을 `상태: 반영됨 <시각>` 으로 표시합니다.
3. 노션 도구가 **없으면** 큐에 남겨둔 채 `SESSION-LOG.md` 에 "노션 미동기화 N건"으로 적고, 이 대화창에 보고합니다.

**노션 기록 원칙**: 못 한 것을 했다고 쓰지 않습니다. 확인 못 한 항목은 "확인 불가 — 사유".

## 원격 컨테이너 주의
로컬 스케줄러가 없어 **컨테이너 자체의 자동 실행은 없습니다.** 정기 실행은 Claude Routine 이 이 대화창을 깨우는 방식이며, 결과는 **커밋해야만** 남습니다.
