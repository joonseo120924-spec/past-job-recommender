# 🏢 조직도 — 6본부 20명 + 독립 감사관

> 규정 정본은 `.claude/team-rules.md` 입니다. 충돌 시 그쪽이 우선합니다.

**앱 하나를 4일 주기로 만드는 AI 조직.**

```
                    🎖️ 마스터 (총괄 · 유일한 배정권자)
                                │
 ┌────────┬────────┬────────┬───┴────┬────────┬────────┐
① 전략 → ② 프로덕트 → ③ 디자인 → ④ 개발 → ⑤ 품질 → ⑥ 출시운영
                                    ↑         │
                                    └─────────┘ 오류 있으면 되돌림

              🎖️ team-master (독립 감사관 — 마스터까지 감시)
```

| 본부 | 파트장 (승인권) | 실무자 (병렬 실행) | 하는 일 |
|---|---|---|---|
| ① 전략 | `strategy-lead` | `market-analyst` · `competitor-analyst` · `user-researcher` | 뭘 만들지 정한다 |
| ② 프로덕트 | `product-planner` | `ux-designer` · `system-architect` | 개발자가 질문 없이 만들 수 있게 설계 |
| ③ 디자인 | `design-lead` | `ui-designer` · `brand-designer` | 어떻게 보이는지 + 접근성 검증 |
| ④ 개발 | `tech-lead` | `frontend-dev` · `fullstack-dev` | 실제로 돌아가는 코드 |
| ⑤ 품질 | `qa-lead` | `functional-tester` · `security-tester` | 가장 무거운 권한 |
| ⑥ 출시운영 | `gtm-lead` | `store-release` · `ops-manager` | 복붙만 하면 되게 |
| 감사실 | `team-master` (독립) | — | 마스터까지 감시 |

**실무자는 승인권이 없습니다.** 파트장이 배정·검토·승인합니다.

## 지휘 체계 — 파트장 2회 호출
서브에이전트는 다른 서브에이전트를 호출할 수 없습니다. 그래서 이렇게 돕니다.

```
파트장 1차 → 분배안 작성 → 반드시 파일로 저장
     ↓
마스터가 분배안대로 실무자를 병렬 호출  ← 속도의 핵심
     ↓
파트장 2차 → 분배안 파일 다시 읽고 통합·검토·파트 승인
     ↓
마스터 게이트 심사 (파일을 직접 열어 확인)
     ↓
감사관 판정 → 반려되면 진행 불가
```

## 4일 주기
| 일차 | 목표 |
|---|---|
| 1일차 | ① 전략 → ② 프로덕트 |
| 2일차 | ③ 디자인 → ④ 개발 |
| 3일차 | ⑤ 품질 (오류 0개까지) |
| 4일차 | ⑥ 출시운영 → 최종 보고서 |

5일차 = 다음 앱 1일차. 4일 안에 못 끝내면 **미완인 채로 종료하고 사유를 기록**합니다.
