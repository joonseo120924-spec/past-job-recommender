## 지휘 체계 — 파트장 2회 호출

서브에이전트는 다른 서브에이전트를 호출할 수 없습니다. 그래서 이렇게 돕니다.

```
파트장 1차 → 분배안 작성 → 반드시 파일로 저장
     ↓
마스터가 분배안대로 실무자를 병렬 호출  ← 속도의 핵심
     ↓
파트장 2차 → 분배안 파일 다시 읽고 통합·검토·파트 승인
     ↓
마스터 게이트 심사 (파일을 직접 열어 확인)
     ↓
감사관 판정 → 반려되면 진행 불가
```

## 게이트 — 못 지나가면 못 갑니다

| 게이트 | 조건 |
| --- | --- |
| **④ 개발 착수** | 8항목 전부: 시장분석·아이디어승인·기능정의·화면설계·데이터구조·API정의·예외정의·**디자인승인** |
| **⑤ QA 착수** | 5자료 전부: 최신코드·변경내역·기능목록·테스트방법·알려진제한사항 |
| **⑤ QA 완료** | 20회 이상 테스트 + **남은 오류 0개** · 실행 로그. `TODO` 나오면 반려 |
| **③ 디자인 완료** | 대비비를 **실제 계산값**으로 제시. "충분해 보임"은 반려 |
| ④↔⑤ 반복 | 최대 3회. 초과 시 중단하고 사용자 보고 |

## 4일 주기

| 일차 | 목표 |
| --- | --- |
| 1일차 | ① 전략 → ② 프로덕트 |
| 2일차 | ③ 디자인 → ④ 개발 |
| 3일차 | ⑤ 품질 (오류 0개까지) |
| 4일차 | ⑥ 출시운영 → 최종 보고서 |

5일차 = 다음 앱 1일차. 4일 안에 못 끝내면 **미완인 채로 종료하고 사유를 기록**합니다.
