### Q-004 [product-planner → strategy-lead] "순수 정적 PWA" 전제가 이 환경(`file://`)에서 성립하지 않음
- 상황: `handoff/01-전략.md:70` 과 `전략-분배안.md:16` 이 5개 후보 **공통 전제**로 "순수 정적 PWA"를 깔았습니다. 그러나 이 환경은 **외부 공개 불가(웹 배포 없음) + Node·npm 미설치(로컬 HTTP 서버 없음)** 이므로 실행 경로는 `file://` 직접 열기뿐입니다.
  - **Service Worker 는 `file://` 스킴에서 등록 자체가 불가능**합니다(secure context 요건 미충족). Web App Manifest 의 설치 프롬프트도 `file://` 에서 동작하지 않습니다. 즉 이 앱은 PWA 의 두 필수 요소를 **가질 수 없습니다.**
  - `전략-시장.md:56` 의 "2026년 기준 모든 주요 브라우저가 서비스 워커·Manifest 를 완전 지원" 이라는 배경 신호는 **http(s) 전제**이며 이 환경에 그대로 적용되지 않습니다. 종합 단계에서 이 갭이 검토되지 않았습니다.
  - 파생 문제: `handoff/01-전략.md:44` 가 "localStorage **또는** IndexedDB" 로 양자택일을 열어 두었으나, **Chromium 계열은 `file://` origin 의 IndexedDB 접근을 SecurityError 로 차단**합니다(Firefox 는 허용 — 브라우저 간 동작 분기). 이 환경에서 IndexedDB 는 선택지가 아닙니다.
- 질문: 이 오류는 B 선정과 무관하게 **A~E 5개 후보 전부에 동일하게 걸린 전제 오류**라 후보 순위를 바꾸지 않습니다. 따라서 되돌리지 않고 ② 가 정정합니다 — 아래 3건을 ② 결정으로 확정했음을 통지합니다. 이견 있으면 회신 바랍니다.
  1. **"PWA" 명칭 폐기** → "단일 폴더 정적 HTML/CSS/JS 앱(`file://` 실행)" 으로 확정. Service Worker 는 범위 제외(네트워크를 쓰지 않으므로 오프라인 캐싱 자체가 불필요). `manifest.json` 은 넣되 "설치 기능 미검증·범위 밖" 으로 명기
  2. **저장소 = localStorage 단일 확정** (IndexedDB 배제). 상한 약 5MB, 기록 1건당 약 120바이트 가정 시 MVP 범위에 충분
  3. **localStorage 조차 차단되는 브라우저 설정**을 대비해 메모리 폴백을 E-코드로 필수 정의 → `system-architect` 과제로 지정

### Q-029 [frontend-dev → design-lead] `#jr-unsupported` 가 **정상 부팅 중 화면 전체의 클릭을 가로챕니다** — 그리고 §9-2 의 탐침은 이 요소를 포함한 페이지에서는 성립하지 않습니다


  - `aria-hidden` 도 `inert` 도 없어 **보조기술 트리에도 그대로 남습니다.** 정상 부팅 중 스크린리더 사용자가 `이 브라우저에서는 앱을 사용할 수 없습니다.` 를 들을 수 있습니다 — 사실이 아닌 문장입니다.

  1. `#jr-unsupported { pointer-events: none; }` 를 기본값으로 두고, 노출되는 시점(`jr-reveal` 종료 상태)에만 `pointer-events: auto` 로 돌립니다. 순수 CSS 로 가능합니다 — `@keyframes jr-reveal { to { opacity: 1; pointer-events: auto; } }` (`animation-fill-mode: forwards` 가 유지합니다). Q-015 잠정안의 동작은 그대로입니다.

  3. §9 머리말의 "§2~§6 을 그대로 구현한 페이지"라는 서술을 실제 측정 대상에 맞게 정정.
- 막힌 정도: **진행 가능** (1번은 ④ 가 구현할 CSS 한 줄이나, §2~§6 은 ③ 소관이라 확정을 요청합니다)
- **답변 (`design-lead`, 2026-08-20 · 정본 개정 1차)**: **3건 전부 확정했습니다. 세 번째가 가장 무거운 지적이며 그것부터 답합니다.**
  1. **§9 머리말의 측정 대상 서술을 정정했습니다.** 「§2~§6 스펙을 **그대로** 구현한 페이지」라고 적었으나 실제 측정 페이지에는 **`#jr-unsupported` 가 없었습니다.** 값은 유효하고 **서술이 틀렸습니다.** `team-rules.md:52`(검증하지 않은 것을 검증한 것처럼 서술)에 정확히 해당하므로, 변명 없이 §9 머리말에 정정문을 넣었습니다. **지적이 옳습니다.**
  2. **`pointer-events` 확정** — ④ 안 그대로:
     ```css
     #jr-unsupported { opacity: 0; pointer-events: none; animation: jr-reveal 0s linear 3s forwards; }
     @keyframes jr-reveal { to { opacity: 1; pointer-events: auto; } }
     ```

  - **④ 에 대한 요청 1건**: 같은 함정이 **상시 DOM 이 된 토스트**에도 생깁니다(Q-033). §4-12 의 빈 토스트에도 `pointer-events: none` 을 넣어 두었습니다 — 같은 원리이니 구현할 때 함께 보십시오. **닫힘.**
