## 3. 파트장 직접 재현 — **실무자 결론을 그대로 받지 않았습니다**

새로 짠 스크립트 6개로 재현했습니다(실무자 스크립트 미사용). **결과: 실무자 보고의 사실관계는 정확했고, 서술 2건이 부정확해 정정합니다.**

### 3-1. QA-S-002 — 재현 · **피해가 보고서보다 더 무겁습니다**

사용자가 **「아이 학원비」를 골라 삭제**했을 때 실제로 일어난 일:

```
원자료: {"before":["건강검진비","아이 학원비","일반중복A"],
         "after":["아이 학원비","일반중복A"],
         "deletedOk":true,
         "지운다고고른것":"아이 학원비",
         "실제사라진것":["건강검진비"],
         "아직남은것":["아이 학원비","일반중복A"]}
```

- 고른 것(`아이 학원비`)은 **그대로 남아 있고**, 고르지 않은 것(`건강검진비` 40만원)이 **사라졌습니다.**
- 반환값은 `ok:true` — **앱은 성공했다고 답합니다.**
- **대조군이 이것을 결함으로 확정합니다**: 같은 파일의 평범한 중복 id `dup1` 은 정확히 **1건으로 거부**됩니다(가드 동작). `__proto__` 만 2건이 통과합니다.
- 원인: `seen['__proto__'] = true` 가 `__proto__` 세터를 타고 들어가 **own 속성이 생기지 않으므로** 다음 `hasOwnProperty` 검사가 계속 `false`. 그 뒤 `model.js:182 findExpense` 가 **첫 일치 인덱스**를 지웁니다.

**S1 유지.** 지출 기록 앱에서 「지우라고 하지 않은 돈이 조용히 사라지고, 지우라고 한 것은 남는다」는 데이터 손실입니다.

### 3-2. QA-S-001 — 재현 · **잔존물은 무조건, 부활은 조건부입니다 (보안 보고서 한 줄 요약을 정정)**

보안 보고서 §11 은 「**다음 부팅에서 화면에 되살린다**」로 적었습니다. **무조건이 아닙니다.** 3시나리오로 갈라 쟀습니다.

| 시나리오 | 전체 삭제 후 잔존 키 | 잔존물에 메모 원문 | 재부팅 후 화면 부활 | 총합 |

| **A. 전체 삭제만** | `jr.v1.expenses.bak` · `jr.v1.categories.bak` | **있음** | **없음** | `0원` |
| **B. 이후 메인 키 손상**(쓰기 중단 흉내) | 〃 | **있음** | **치과 진료비 · 월세 이체 · 심야 택시 전부 부활** | **`66,000원`** |
| **C. 이후 메인 키가 비-배열** | 〃 | **있음** | **전부 부활** | **`66,000원`** |

B·C 에서 화면에 뜬 배너: **「저장된 데이터 일부가 손상되어 백업본으로 되살렸습니다.」**

**정정된 사실관계 — 그래도 S1 입니다.**
1. **잔존은 무조건입니다**(A·B·C 전부). 사용자가 「전체 삭제」를 눌렀는데 **지출 메모 원문이 `localStorage` 에 그대로 남습니다.** 이것만으로 「전체 삭제」라는 **사용자 명령의 계약 위반**입니다.
2. **부활 경로는 앱이 스스로 갖춘 복구 경로입니다**(`model.js:368 loadKeyWithRecovery` → E-303/E-304). 팀이 「도달한다」고 보고 만들어 둔 경로입니다. 도달 불가능한 가정이 아닙니다.
3. 부활 시 앱은 **「되살렸습니다」라고 사용자에게 알리면서** 사용자가 지운 데이터를 복원합니다.

→ **보안 보고서의 요약 한 줄을 「메인 키가 읽히지 않게 되는 순간 되살아난다」로 정정**하고 S1 을 유지합니다. ⑥ 출시가 이 문장을 「무조건 부활」로 인용하면 안 됩니다.

## 4. `E-123` 을 S2 로 올립니다 — **파트장 신규 실측**

② 와 두 실무자는 **「`E-123` 발생 지점 0건 + `maxlength=100` 잔존」이라는 정적 사실**까지만 적었습니다.
파트장이 **실사용 피해를 직접 쟀습니다.**

```
=== E-123 / maxlength 단일기준 위반의 실피해 (Chromium · #jr-memo 실타이핑) ===
 "한글 100자":                    { 입력하려던_코드포인트: 100, 실제들어간_코드포인트: 100, countChars판정: 100 }
 "이모지 100자(계약상 정확히 상한)": { 입력하려던_코드포인트: 100, 실제들어간_코드포인트:  50, countChars판정:  50 }
 maxlength 속성값 = 100
```

- 계약(Q-008 확정)은 **`JR.model.countChars` 단일 기준 = 코드포인트**입니다. 이모지 100자는 **정확히 상한**입니다.
- 그런데 `maxlength="100"` 은 **UTF-16 코드 단위**로 셉니다. 이모지는 1자당 2단위 → **50자에서 입력이 잘립니다.**
- 잘렸다는 **통지는 없습니다.** `E-123` 은 정의(`err.js:47`)와 우선순위 배열(`ui.js:40`)에만 있고 **`show('E-123')` 호출 지점이 0건**이기 때문입니다.

**→ 「문서 위반」이 아니라 「사용자 입력이 통지 없이 절반 소실」입니다. 분배안 §7 「기능이 목적을 달성 못 함」에 해당해 S2 로 올립니다.**
② 가 `maxlength` 제거를 시정 필수로 확정한 것은 옳았고, **심각도가 과소평가되어 있었습니다.**

## 5. 기준선 정정 — 비-`{ok}` 는 **12도 17도 18도 아닙니다**

### 5-1. 확정: **계약 범위 18개 · `JR.ui` 10개 · 전 표면 28개**

파트장이 **정적 전수 감사 + 런타임 전수 census 를 새로 짜서** 3엔진(Chromium·Firefox·WebKit)에서 돌렸습니다.
**표면 함수 75개 전건 호출** — 하나도 빼지 않았습니다.

| 범위 | 개수 | 명단 |
|---|---|---|
| **계약 대상 5모듈** (`err`·`store`·`model`·`stats`·`io`) | **18** | `err.get` `err.slot` `err.format` **`err.log`** / `store.mode` / `model.isReady` `today` `minDate` `maxDate` `countChars` `normName` `shiftMonth` `monthRange` `isNoticeDismissed` / `stats.allocatePercents` `formatAmount` `invalidate` / **`io.readFile`** |
| **`JR.ui`** (계약 범위 **밖** — 분할안 §5-2 각주가 명시) | **10** | `init` `show` `showErrors` `toast` `toastText` `inline` `banner` `dismissBanner` `lock` `unlock` |
| **합계 (전 표면)** | **28** | 함수 75개 중 `{ok}` 준수 47 · 비-`{ok}` 28 |

3엔진 전부 동일. `pageerror` 0.

### 5-2. **숫자가 우연히 같아서 더 위험합니다**

기능 시험자의 **18**과 계약 범위의 **18**은 **같은 숫자이지만 다른 명단**입니다.

| | 기능 시험자의 18 | 계약 범위의 18 (정본) |
|---|---|---|
| 들어 있는데 없어야 할 것 | `ui.lock` · `ui.unlock` (계약 범위 밖) | — |
| 없는데 있어야 할 것 | — | **`err.log`** · **`io.readFile`** |

**「18로 맞았다」고 넘어가면 `err.log`·`io.readFile` 이 영영 안 잡힙니다.** 명단으로 확정합니다.

### 5-3. **왜 세 번이나 틀렸는가 — 원인은 「숫자」가 아니라 「세는 도구」입니다**

세 번의 정정은 각각 다른 사람의 실수가 아니라 **같은 도구의 같은 사각을 세 번 물려받은 것**입니다.

| 차수 | 숫자 | 어떻게 얻었나 | 무엇이 사각이었나 |
|---|---|---|---|
| 1차 (④) | **12** | 계약 문서 `개발-분할안.md:298` 의 목록을 **옮겨 적음** | **측정이 아님.** 같은 문서 §5-3·§5-4 예시 코드가 4개를 더 비-`{ok}` 로 쓰라고 지시 → 문서 자기모순 |
| 2차 (②·파트장) | **17** | `verify/ok.cjs` 실행 → **`개수: 16`** + 루프 밖에서 손으로 보탠 `ui.lock` 1 | **`ok.cjs` 의 사각 2개를 그대로 물려받음**(아래) |
| 3차 (⑤ 기능) | **18** | 「6모듈 40개 표면 전수 호출」 | **표면은 40이 아니라 85**(함수 75 + 상수 10). `ui` 에서 2개만 잡힘 |
| **4차 (파트장·확정)** | **28** | **도구를 새로 짬** — 정적 전수 + 런타임 전수, `ui` 포함 | 사각 제거 |

**`verify/ok.cjs` 의 사각 2개 — 코드로 확인했습니다.**

```js
// ① ui 가 열거 루프 밖에 있다 — ui.lock 한 개만 손으로 출력한다
['err','store','model','stats','io'].forEach(mod => { … });
console.log('=== JR.ui.lock 반환 타입 ===', res.uiLock);

// ② args 하드코딩 화이트리스트에 없는 함수는 조용히 카운트에서 빠진다
if(!(key in args)){ out.push({key, kind:'미호출(인자 불명)'}); return; }
```

파트장이 `ok.cjs` 를 직접 돌린 출력:
```
개수: 16
=== 인자 불명으로 미호출 === 23
   err.log · store.getRaw · … · io.download · io.readFile · io.applyImport
=== JR.ui 표면 === init, show, showErrors, toast, toastText, inline, banner, dismissBanner, lock, unlock, MSG, TOAST_MS
```

**산수가 정확히 닫힙니다**: `16` (부분 측정) `+ 2` (미호출 23개 중 비-`{ok}` 인 `err.log`·`io.readFile`) `+ 10` (`ui` 함수 전체) **`= 28`**.

> ### 원인 한 줄
> **`개수: 16` 은 「비-`{ok}` 함수의 개수」가 아니라 「하드코딩 인자 목록에 우연히 들어 있던 함수 중, 6모듈 가운데 5모듈에서 세어진 비-`{ok}` 함수의 개수」였습니다.**
> 그런데 아무도 그 **범위를 문서에 적지 않았습니다.** 세 번의 정정은 모두 **범위를 정의하지 않은 채 숫자만 고친 것**이라, 매번 새 사각에서 새 항목이 튀어나왔습니다.
>
> **파트장 귀책을 먼저 적습니다.** 2차 정정(17)을 확정한 것은 **파트장 자신**입니다.
> 파트장은 `ok.cjs` 의 사각을 §3-1 에 **정확히 설명해 놓고도**(「`ui` 는 루프 밖」), **사각을 없애는 대신 손으로 1개를 보태 숫자를 맞췄습니다.**
> **설명할 수 있는 사각은 고쳐야지 보정해서는 안 됩니다.** 세 번째 정정을 부른 것은 그 판단입니다.

### 5-5. QA-F-002 재판정 — **코드 결함이 아니라 기준선 결함**
