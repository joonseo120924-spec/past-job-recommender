## 0. 전제 — 이 환경의 제약 (조사 범위를 미리 좁히는 이유)

사이클 1(FocusNoise, 동결)에서 확정된 제약이 사이클 2에도 그대로 적용됩니다. 세 분은 조사 결과에 이 제약과 **명백히 맞지 않는 후보**(서버 필요, 로그인/동기화 필요, 유료 API 의존 등)를 발견하면 "부적합" 이라고 명시만 하고, 후보를 임의로 바꾸지 마십시오 — 후보 조정은 종합 단계(② 전략본부 2차 호출)에서 제가 합니다.

- 실행 환경: Linux 원격 컨테이너, 세션 종료 시 소멸 → **저장소에 커밋된 것만 남는다**
- 돈이 나가는 것 전부 RED — 유료 API, 유료 SDK, 개발자 계정, 도메인 구매 불가
- 외부 공개 RED — 스토어 제출, 웹 배포 불가. 산출물은 **저장소 안에서 완결**
- 사이클 1과 동일하게 **순수 정적 PWA**(외부 네트워크 요청 0건, 완전 오프라인)를 기본 전제로 조사
- ①~⑥ 전체를 4일 안에 끝내야 함 → 기능 범위가 좁아야 완성 가능한 후보가 유리

이 제약이 의미하는 것: **로그인/서버 동기화/광고/구독/유료 API가 있는 경쟁 앱과는 애초에 "돈을 안 받는다"는 축에서 차별화된다.** 세 분 모두 이 축을 의식하고 조사해 주십시오 (특히 competitor-analyst의 페이월 조사, user-researcher의 이탈 이유 조사).

## 1. 조사 대상 후보 5개 (공통)

세 분 모두 **같은 5개 후보**를 각자의 관점(시장/경쟁/사용자)에서 조사합니다. 후보를 나눠 맡는 것이 아니라 **관점을 나눠 맡습니다** — 그래야 종합 단계에서 후보별로 세 축을 나란히 비교할 수 있습니다.

| # | 후보 | 한 줄 설명 |
|---|---|---|
| A | 오프라인 습관 트래커 | 매일 체크인 + 연속기록(streak) + 로컬 통계, 계정 없이 기기에만 저장 |
| B | 오프라인 가계부 / 지출 계산기 | 수기 입력형 지출 기록 + 카테고리별 통계, 은행 연동 없음 |
| C | 암기 플래시카드 (간격반복 SRS) | 사용자가 카드덱을 직접 만들고 SRS 알고리즘으로 복습 일정 산출, 로컬 저장 |
| D | 텍스트 유틸리티 툴박스 | 마크다운 미리보기 · JSON/YAML 정리 · 단위 변환 · 텍스트 diff 등 오프라인 도구 모음 (개발자/직장인 대상) |
| E | 레시피 & 장보기 플래너 | 레시피 로컬 저장 + 선택한 레시피들의 재료를 합쳐 장보기 리스트 자동 생성 |

조사 중 이 5개 외에 뚜렷한 신호(예: 사용자 불편사항이 유독 많이 몰리는 인접 카테고리)를 발견하면 각자 산출물 맨 아래 "추가 발견" 절에 적어 주십시오. 다만 본 조사의 주력은 A~E 5개입니다.

## 2. 담당별 분배

### 2-1. `market-analyst` — 시장 조사
**산출물**: `ai-team/apps/2026-08-11/docs/전략-시장.md` (형식은 본인 agent 정의의 `## 카테고리: <이름>` 포맷 그대로)

- A~E **각 후보마다** 카테고리 절을 하나씩 만들어 다음을 조사:
  - 해당 카테고리(습관 트래커 / 가계부 앱 / 플래시카드 앱 / 개발자 유틸리티 도구 / 레시피 앱)의 시장 규모·인기도·검색 수요 신호 (앱스토어 카테고리 순위, 검색 트렌드, 다운로드/설치 통계 등)
  - 성장 추세 (최근 관심 증가/감소)
  - **PWA·오프라인·무료 세그먼트로 좁힌 데이터가 있으면 별도로 표시.** 없으면 카테고리 전체 데이터를 쓰되 "PWA 특화 데이터 아님 — 참고용" 이라고 명시
- 마지막 절 "해석": 5개 후보를 시장 규모/성장세 기준으로만 상대 비교 (다른 축은 다루지 말 것 — 그건 종합 단계 몫)
- 수치에는 반드시 출처 URL + 조사일자. 못 찾은 항목은 "추정치 — 미검증" 또는 "확인 불가 — 사유"로 명시

### 2-2. `competitor-analyst` — 경쟁 조사
**산출물**: `ai-team/apps/2026-08-11/docs/전략-경쟁.md` (형식은 본인 agent 정의의 `## <앱 이름>` 포맷 그대로)

- A~E **각 후보마다** 대표 경쟁 앱을 2~3개씩 선정해 조사 (플랫폼 무관 — 웹/iOS/Android 모두 가능)
- 각 앱마다 **페이월 위치를 정확히**: "무료로 어디까지 되고, 어디서부터 결제/로그인/동기화를 요구하는가"를 구체적으로 (예: "무료 카드 30장까지, 무제한은 월 구독" / "로컬 저장은 무료, 클라우드 동기화만 유료")
- 강점은 그대로 인정하고 적을 것. 리뷰 근거 기반 약점도 함께
- 마지막 절 "해석": 5개 후보 중 **"돈 안 받는 정적 오프라인 버전"으로 차별화 여지가 가장 큰 후보**를 순위만 매기고 이유를 1~2줄로 (최종 판단 아님 — 재료 제공)

### 2-3. `user-researcher` — 사용자 조사
**산출물**: `ai-team/apps/2026-08-11/docs/전략-사용자.md` (형식은 본인 agent 정의의 `## 불편사항: <한 줄 요약>` 포맷 그대로)

- A~E **각 후보 카테고리마다** 실제 사용자 리뷰/커뮤니티 글에서 불편사항 최소 2건씩 수집 (앱스토어 리뷰, 커뮤니티 게시판 등)
- 특히 다음 유형의 불만을 우선 채집: 로그인 강요, 광고, 구독 결제, 오프라인에서 안 됨, 인터넷 필요, 데이터 유출 우려 — **이 제품이 정적 오프라인 무료로 풀 수 있는 불만인지** 여부가 종합 단계에서 핵심 재료가 됩니다
- 원문 인용 3줄 이내 + 출처 URL, 언급 빈도(N건/조사 M건) 명시. "사용자는 X를 원한다" 식 단정 금지
- 개인정보(실명·아이디·프로필 링크) 전재 금지

## 3. 종합 단계 판단 기준 (2차 호출에서 사용 — 미리 공지)

세 분의 조사 결과가 들어오면 저(strategy-lead)는 A~E 5개 후보를 아래 기준으로 100점 만점 채점해 비교하고, `product-planner` 검토 후 1위를 승인합니다. 사이클 1 FocusNoise(85점) 선정과 같은 형식입니다.

| 기준 | 배점 | 판단 근거로 쓰는 조사 |
|---|---|---|
| 사용자 가치 | 30 | user-researcher — 실제 불편사항을 얼마나 직접 해결하는가 |
| 차별점 | 25 | competitor-analyst — 경쟁 앱의 페이월/제약 대비 "무료·오프라인"으로 얼마나 벌어지는가 |
| 4일 내 완성 가능성 | 25 | 3인 공통 — 기능 범위가 좁고 정적 데이터/로컬 연산만으로 충분한가 |
| 기술 제약 충족 | 20 | 3인 공통 — 외부 API·서버·결제·계정 없이 완전 오프라인 정적 PWA로 구현되는가 |
| **합계** | **100** | |

**반려 기준**: 출처 URL 없이 적힌 수치가 하나라도 있으면 해당 실무자 산출물 전체를 반려하고 재조사를 요청합니다.
