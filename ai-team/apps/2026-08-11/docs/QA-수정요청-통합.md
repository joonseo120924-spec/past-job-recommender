## 2. 순차 적용 순서 — **파트장이 지정합니다. 병렬로 고치지 마십시오**

병렬 수정은 덮어쓰기를 만듭니다. **아래 순서대로 하나씩, 각 단계마다 재현 스크립트를 돌려 확인한 뒤 다음으로** 넘어가십시오.

### 1단계 — `__proto__` 계열 (S1 1건 + S2 2건) · **결정 Q-068 이 먼저**

`io.js:171,188,235,246,260-261` · `model.js:324,361,782`

- **원인**: `var seen = {};` 에 `seen['__proto__'] = true` 를 하면 `__proto__` **세터**를 타고 들어가는데, `true` 는 객체가 아니므로 **조용히 무시**됩니다. own 속성이 생기지 않아 다음 `hasOwnProperty` 검사가 계속 `false` 입니다.
- **대조군이 이것을 결함으로 확정합니다**: 같은 파일의 `dup1`(일반 id)·`커피`(일반 이름)·`constructor`(own 속성이 생기는 키)는 **정확히 1건으로 걸러집니다.** `__proto__` 만 통과합니다.
- **권장 조치 (Q-068 결정 후)**: 누산기를 `Object.create(null)` 로 바꾸는 **한 가지 방식으로 8곳 전부**. 개별 키 블랙리스트는 `constructor`·`prototype` 등에서 다시 새므로 권하지 않습니다.
- `model.js:782 getCategoryMap` 도 **같은 조치 대상**입니다 — 여기는 `map` 자체가 `Object.create(null)` 이어야 프로토타입 교체가 막힙니다.

**검증 기준 (이것이 통과해야 1단계 완료)**
```
id='__proto__' 2건 가져오기 → 저장 건수 1 (현재 2)
name='__proto__' 2건 가져오기 → 카테고리 1개 (현재 2)
categoryId='__proto__' → Object.getPrototypeOf(getCategoryMap()) 가 교체되지 않음
대조군 dup1·커피·constructor 는 기존대로 1건 유지 (회귀 금지)
사용자가 고른 기록만 삭제됨 ← S1 의 본체입니다. 반드시 이 항목까지 확인하십시오
```
