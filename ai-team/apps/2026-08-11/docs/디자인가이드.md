## 3. 타이포 스케일

| 토큰 | 크기 | `line-height` | `font-weight` | 용도 |
|---|---|---|---|---|
| `--jr-fs-sm` | 14px | 1.6 | 400 | 보조 텍스트 · `0/100` 카운터 · 비율 텍스트 · 인라인 오류 · 배너 본문 · 토스트 본문 · 탭 라벨 |
| `--jr-fs-base` | 16px | 1.6 | 400 본문 / 600 버튼·입력값 | 본문 · 버튼 라벨 · 입력값 · 목록 행 |
| `--jr-fs-lg` | 18px | 1.3 | 700 | 구역 제목 · 월 표시 · 대화상자 제목 |
| `--jr-fs-xl` | 22px | 1.3 | 700 | **S-01 화면 제목 `한달정리` 단 한 곳** |
| `--jr-fs-amount` | 28px | 1.3 | 700 | S-01·S-03 총합 금액 |

- **14px 미만 0건** — 렌더 후 전 텍스트 노드 실측 확인(§9-6).
- 1.3 을 쓰는 세 토큰은 전부 한 줄로 끝나는 제목·금액이며 "본문"이 아닙니다. 본문 1.6 강제는 `--jr-fs-sm`·`--jr-fs-base` 에 적용됩니다.
- 금액이 나오는 모든 자리에 `font-variant-numeric: tabular-nums` + `var(--jr-font-num)`. **`font` 단축 속성은 `font-variant-numeric` 을 초기화하므로 반드시 단축 속성 뒤에 선언하십시오.**

## 4. 컴포넌트 13종

공통(반복 표기 생략):
- 포커스 표시는 §2 전역 규칙. **`box-shadow: inset` 대체 금지** — `--jr-focus` 대 `--jr-brand` 는 **1.04:1** 이라 브랜드색 위에 그리면 보이지 않습니다.
- 모든 조작 요소 히트 영역 **44×44px 이상** (§9-2 실측).
- 인접 조작 요소 히트 간격 **8px 이상**, **파괴적 동작 옆 12px 이상** (§9-3 실측).
- hover/pressed 는 새 색 토큰 없이 `--jr-text` 알파 오버레이 — 합성 결과 대비는 §9-1 에서 전부 계산했습니다.

테두리는 비활성에서도 **유지**합니다(형태 정보). `--jr-divider` 로 낮추지 마십시오. 테두리 대비: 흰 배경 위 **3.65:1**, `--jr-surface` 위 **3.37:1**, `--jr-surface-sunken` 위 **3.10:1** — 전부 3:1 통과.

> 내보내기 대체 영역(`--jr-surface` 패널) 안의 `전체 선택` 버튼은 **면 자체가 패널과 1.08:1** 이라 보이지 않습니다. 이 버튼을 식별시키는 것은 **오직 테두리(3.37:1)** 입니다. 테두리를 지우면 버튼이 사라집니다.

**선택 상태의 색 외 신호 — 파트장 재확정 (§10-5)**

`ui-designer` 가 쓴 `1.5px solid var(--jr-on-brand)` 는 **흰 페이지 배경 위의 흰 테두리(1.00:1)** 라 신호로 존재하지 않습니다. 폐기하고 아래 3중으로 확정합니다.

| 신호 | 실측 근거 |
|---|---|
| **채움 명도 반전** | 선택 `#0B6B5B` 대 미선택 `#F4F6F8` = **5.93:1**. 색상(hue) 차가 아니라 **명도** 차이므로 흑백·전색맹에서도 구분됩니다 |
| `font-weight` 500 → 600 | 형태 신호 |
| `aria-checked` / `role="radio"` | 프로그램적 신호 |

테두리를 1px 로 통일한 부수 효과: **선택 전환 시 칩 폭이 바뀌지 않습니다** — 실측 선택 66.00px / 미선택 66.00px (§9-8). 1.5px 였다면 20개 칩이 줄바꿈 위치를 바꿔 다른 칩이 다른 줄로 튀었습니다.

- 그룹은 **탭 정지점 1개**, 내부 이동은 좌우 방향키(roving `tabindex`). ④ 구현.
- 줄 수 실측(§9-8): 20개일 때 **360px 폭 7줄(그룹 높이 356px) · 520px 폭 5줄**. 가로 넘침 없음.

### 9-2. 터치 영역 44×44px — 실제 히트 영역 탐침 (전수)

`elementFromPoint` 로 1px 씩 훑어 **의사요소 확장을 포함한 실제 클릭 가능 범위**를 측정했습니다. 대상 32개(360px·520px 각각).

| 결과 | 건수 |
|---|---|
| 44×44 통과 | **30 / 32** |
| **미달** | **2** — `.jr-btn--sm`(`이름변경`) 히트 **96×43** |

- 미달 원인: 시각 높이 36px + `::before{inset:-4px}` = 명목 44px 이지만, 행이 소수점 위치에 놓이면 **정수 픽셀로 실제 히트 가능한 행이 43개**가 됩니다. `삭제` 는 우연히 44 로 떨어졌습니다 — 즉 **위치 운에 따라 통과/미달이 갈리는 설계**였습니다.
- **조치**: `.jr-btn--sm { height: var(--jr-touch) }`, `::before` 확장 폐기. **시정 후 재측정: `이름변경` 90×45 · `삭제` 56×45 — 전 32개 통과.**
- `box-sizing: border-box` 가 없으면 `height:44px` + `border:1px` 인 보조 버튼이 46px 이 되는 등 값이 전부 어긋나므로 §2 에서 전역 선언을 필수화했습니다.

| `outline: none` 대체 없이 사용 | **0건** |
| 링 대비 | 페이지 6.70 / 카드 6.18 / 배너 5.66~6.08 / 비활성면 5.69 — 전부 3:1 통과 |
| **탭바 탭** | 바깥 링(offset 2px)의 **아래 변이 뷰포트 밖 5px** — 실측(탭 하단 900px = 뷰포트 높이 900px, 링 하단 905px). → **`outline-offset: -3px`** 로 시정 |
| **목록 행** | 행 간격 **0px** 이라 바깥 링이 위아래 행을 5px 씩 침범. → **`outline-offset: -3px`** 로 시정 |
| 안쪽 링의 가시성 | 행·탭 배경이 `--jr-bg`/`--jr-surface` 이므로 **6.70:1 / 6.18:1** — 안쪽으로 옮겨도 보입니다 |
| `box-shadow: inset` 대체 | 금지 유지 — `--jr-focus` 대 `--jr-brand` **1.04:1** |

`ui-designer` §4-10 의 설명("바깥 2px 을 유지하되 인접 행과 최소 2px 이상 벌어지도록 `margin` 을 추가하지 않음")은 **자기모순**입니다. `margin` 을 추가하지 않으면 행은 맞닿고, 맞닿으면 바깥 링은 반드시 이웃을 침범합니다. 실측으로 확인해 시정했습니다.

### 9-6. 최소 글자 크기 · 줄간격

### 9-7. 확인 불가에서 해제된 항목 (실측으로 닫음)

### 9-9. `prefers-reduced-motion` — 직접 실험

Playwright `reducedMotion: 'reduce'` 로 에뮬레이션 후 계산된 값 확인.

| 요소 | `animation-duration` | `animation-delay` | `transition-duration` |
|---|---|---|---|
| `#jr-unsupported` (리셋 제외 대상) | `0s` | **`3s` 유지** | `0s` |
| 토스트 · 대화상자 · 버튼 | **`0.00001s`** | `0s` | **`0.00001s`** |

**추가 실험 — 예외 처리가 실제로 필요한가**: 같은 리셋을 **적용한** 대조 요소를 만들어 3.4초 동안 관찰했습니다.

| t | 리셋 **제외** 요소 | 리셋 **적용** 요소 |
|---|---|---|
| 0s | `opacity: 0` · delay `3s` | `opacity: 0` · delay **`3s`** · duration `0.00001s` |
| 1.2s | `opacity: 0` | `opacity: 0` |
| 3.4s | `opacity: 1` | **`opacity: 1`** |

**결론**: `animation-duration` 을 0.01ms 로 강제해도 `animation-delay` 는 영향을 받지 않으므로, **리셋을 적용해도 3초 지연은 사라지지 않습니다.** `ui-designer` §5-4 와 파트장 분배안 §2-7 이 적은 사유("지연이 사라져 정상 부팅마다 번쩍인다")는 **틀렸습니다.** 예외 선택자 자체는 무해하고 방어적이므로 **유지하되, 근거 문장을 이 실측 결과로 대체**했습니다(§5-4). 잘못된 근거를 남겨 두면 뒤에 오는 사람이 그 문장을 믿고 다른 판단을 합니다.

## 14. `frontend-dev` 검토 — **미수행**

**이 문서는 `frontend-dev` 의 검토를 받지 않았습니다.** `team-rules.md:29` 가 지정한 디자인 산출물의 검토자이며, 인수인계서 §9-5 의 게이트 조건입니다. 마스터가 별도로 붙일 예정이라고 통지받았고, ③ 파트장이 대신 수행하거나 면제할 수 있는 항목이 아닙니다.

**승인의 전제인가**: **예 — 다만 착수 차단 조건은 아닙니다.**

- 검토가 겨냥하는 위험은 "디자인이 구현 가능한가 · CSS 가 실제로 동작하는가"입니다. 그 위험의 **상당 부분을 파트장이 브라우저 실측으로 직접 줄였습니다** — §2~§6 의 CSS 를 그대로 구현해 렌더했고, 그 과정에서 실제로 동작하지 않는 지점 4건(토스트 폭·히트 영역·포커스링·흰 테두리)을 찾아 고쳤습니다.
- 남는 위험은 **파트장이 구현하지 않은 부분**입니다: 포커스 트랩·roving `tabindex`·토스트 노드 재사용·`boot.js` 와 `#jr-unsupported` 의 경합·`{max}` 치환. 전부 ④ 구현 영역이라 시안 되돌림으로 이어질 가능성이 낮습니다.
- 따라서 이 승인은 **조건부**입니다(§15). `frontend-dev` 검토에서 시안 되돌림이 나오면 **③ 재승인이 필요**합니다.
