## 10. 확인 불가 · 관찰 (결함 아님)

### 10-1. Firefox 헤드리스에서 Tab 순회가 탭바에서 정체 — **확인 불가**

```
chromium TAB16 = ["jr-s01-next","jr-s01-add","BUTTON.jr-tab","BUTTON.jr-tab","BUTTON.jr-tab","BODY.",
                  "jr-s01-prev","jr-s01-next","jr-s01-add", …]          ← 정상 순환
webkit   TAB16 = (chromium 과 동일)                                      ← 정상 순환
firefox  TAB16 = ["jr-s01-next","jr-s01-add","BUTTON.jr-tab","BUTTON.jr-tab", …(14회 연속 jr-tab)]
```

- **앱 코드에 Tab 을 가로채는 곳은 확인 결과 한 군데뿐이며**, 그것은 `ui.js:478` 의 **확인 대화상자 포커스 트랩**(의도된 접근성 구현)입니다. 탭바에는 `tabindex`·`role` 설정도, `keydown` 가로채기도 없습니다(`#jr-tabbar button` 3개 전부 `tabindex=null`).
- 즉 **앱이 만든 포커스 트랩이 아닙니다.** 헤드리스 Firefox 가 Tab 을 브라우저 크롬으로 넘길 때의 `document.activeElement` 보고 차이로 보입니다.
- **실제 Firefox 데스크톱에서 재확인해야 확정할 수 있으나, 이 환경에는 headed 브라우저가 없습니다 → 확인 불가.**
- 분배안 §3-6 대로 **비-기준 엔진 단독 현상이므로 반려 사유로 쓰지 않았습니다.** → **Q-072** 로 ② 에 올립니다.

### 10-2. 실제 Safari(macOS/iOS) — **확인 불가**

- WebKit 엔진은 3엔진 시험에 **실제로 포함**했고 20 사이클 중 4회를 담당했습니다(`store.mode()="persist"` · 콘솔 에러 0).
- 그러나 **headless WebKit ≠ 실제 Safari** 입니다. 파트장이 Q-059 에서 이미 못박은 대로, 이 결과를 **「사파리 통과」로 쓰지 않았습니다.** 「WebKit 엔진에서 측정됨」으로만 기록합니다.

### 10-3. 실제 파일 다운로드(`file://`) — **부분 확인**

- `file://` 에서 다운로드가 차단되는 경로는 `qa-exc.cjs` 예외 7 로 재현했습니다(**텍스트 폴백 노출 · 전체 JSON 담김 · [전체 선택] 동작 · 앱 정상**).
- 실제 OS 파일 저장 대화상자까지는 헤드리스에서 확인할 수 없습니다 → **확인 불가**.

### 10-4. 실기기 터치·스크린리더 — **미수행**

- 44×44 터치영역과 360px 레이아웃은 **계산으로** 확인했습니다. **실제 손가락 터치·VoiceOver/TalkBack 낭독은 이 환경에서 불가** → 미수행.

### 10-5. 5,000건 성능 — **측정했으나 판정 대상 아님**

- 분배안 §3-5 대로 **판정은 1,000건 기준**이며 5,000건 수치는 §7 에 **실측 로그와 함께** 남겼습니다. 정식 최적화 필요 판정은 **② 소관**(Q-062).
