## 2. 공유 계약 — 두 실무자가 **그대로** 사용 (변경 금지)

### 2-1. 앱 이름 — **파트장 확정**

| 항목 | 확정 |
|---|---|
| 앱 이름 | **한달정리** |
| 가칭 `정레` | **폐기.** 어느 산출물에도 다시 쓰지 마십시오 |
| 등장 위치 | **S-01 화면 제목 단 한 곳.** 본문·대화상자·토스트·오류 문구 어디에도 없습니다 |
| 백업 파일명 | `jr-backup-YYYY-MM-DD-HHMM.json` — **이름이 바뀌어도 그대로.** 구조설계 §5-6-1 이 의도적으로 앱 이름을 배제했습니다. 되돌리지 마십시오 |
| 코드 식별자 | 전역 `JR` · localStorage `jr.v1.*` · id `#jr-*` — **전부 그대로.** 이름 변경의 영향을 받지 않습니다 |

**선정 사유** (③ 파트장 판단, `decisions.md` 기록 대상)

1. 이 앱의 축은 "선택된 월"입니다 — S-01·S-03 이 월 상태를 공유하고, 통계도 월 단위이며, 재실행 후에도 월이 유지됩니다(INT-7-6). 이름이 제품의 실제 단위와 일치합니다.
2. "지출"을 이름에 넣지 않았습니다. S-01 한 화면에 `이 달 총 지출` · `+ 지출 추가` 가 이미 있어 제목까지 "지출"이면 같은 단어가 세 번 반복됩니다.
3. **과장 주장이 없습니다.** 기획서 §1-1 금지 표현("가장 빠른"·"경쟁 앱 전부"·"Mint 사용자의 불편 해결")과 충돌하지 않습니다. 기능을 암시하지도 않습니다(예산·알림·연동은 v1 에 없습니다).
4. `정리` 의 로마자 두문자가 `jr` 이라, 이미 고정된 `jr-` 접두사·`JR` 네임스페이스와 어긋나지 않습니다. 접두사를 바꾸지 않는 이유를 사후에 설명할 수 있습니다.

> `brand-designer` 에게: 이름은 확정입니다. 아이콘·파비콘 작업 중 **치명적 문제**(예: 16px 파비콘에서 4자가 판독 불가 — 다만 파비콘에 글자를 넣지 않기로 §5-2 에서 정했으므로 발생하지 않아야 합니다)를 발견하면 **바꾸지 말고 보고만** 하십시오. 판정은 2차 호출 때 파트장이 합니다.

| 현재 탭 (탭바) | 색 + **3px 상단 인디케이터 바** + `font-weight` 600 + `aria-current="page"` |
| 비활성 버튼 | 채움 `--jr-surface-sunken` + **`aria-disabled` / `disabled`** + 커서 `not-allowed`. **라벨 텍스트는 절대 지우지 않습니다**(화면설계 §0-3: 아이콘 전용 버튼 금지) |
| 인라인 오류 (I 슬롯) | 붉은 색 + **경고 아이콘(인라인 SVG, `aria-hidden`)** + 오류 문구 텍스트 + 입력란 테두리 `--jr-danger` 로 변경 + `aria-describedby` 연결 |
| 배너 3종 | 배경색 + **아이콘 3종(서로 다른 모양)** + **닫기 버튼 유무**(차단형에는 없음). 배경색만으로 종류를 구분하게 두면 **반려** |

### 2-6. 간격 · 크기 · 반경 · 계층 토큰

```
--jr-sp-1: 4px    --jr-sp-2: 8px    --jr-sp-3: 12px   --jr-sp-4: 16px
--jr-sp-5: 20px   --jr-sp-6: 24px   --jr-sp-8: 32px   --jr-sp-10: 40px

--jr-radius-sm: 6px      입력란·보조 버튼
--jr-radius-md: 10px     카드·대화상자·배너
--jr-radius-pill: 999px  칩·비율 막대

--jr-touch: 44px         최소 터치 영역
--jr-tabbar-h: 56px      하단 탭바 높이 (S-02 에서는 0)
--jr-maxw: 520px         본문 열 최대 너비(가운데 정렬). 데스크톱 브라우저 대응
```

**z-index 계층 (고정)**

| 층 | 값 | 요소 |
|---|---|---|
| 1 | `20` | 하단 탭바 (fixed) |
| 2 | `30` | B 슬롯 배너 (sticky) |
| 3 | `40` | T 슬롯 토스트 |
| 4 | `50` | 대화상자 뒷막(overlay) |
| 5 | `51` | 대화상자 본체 |

**B 슬롯 배너는 `position: sticky; top: 0` 입니다 — `fixed` 를 쓰지 마십시오.**
사유: `fixed` 는 높이를 레이아웃에서 빼앗아 본문이 가려지거나 배너에 `max-height` 를 걸게 만듭니다. 가장 긴 배너 문구는 **E-201(3문장, 공백 포함 95자 — 실측)** 이고, 인수인계서 §5 가 "이 문구가 화면 상단에서 잘리지 않는지 확인"을 명시적으로 요구했습니다. `sticky` + 높이 자동 + `max-height`·`overflow:hidden` 금지로 **잘림이 구조적으로 불가능**하게 만드십시오.

### 2-7. 타이포 · 모션 토큰

**폰트 스택 (고정 — 외부 폰트 0)**

```css
--jr-font: -apple-system, BlinkMacSystemFont, "Segoe UI", "Apple SD Gothic Neo",
           "Malgun Gothic", "맑은 고딕", "Noto Sans KR", "Nanum Gothic", sans-serif;
--jr-font-num: var(--jr-font);   /* 금액은 font-variant-numeric: tabular-nums 를 함께 지정 */
```

금액이 나오는 모든 자리(총합·목록 행·통계 항목)에 **`font-variant-numeric: tabular-nums`** 를 지정하십시오. 자릿수가 흔들리면 목록에서 금액이 춤춥니다.

**크기 계단** — `ui-designer` 가 아래 이름으로 확정값을 채웁니다. 14px 미만 금지.

| 토큰 | 용도 |
|---|---|
| `--jr-fs-sm` | 보조 텍스트 · `0/100` 카운터 · 비율 텍스트 |

**모션 토큰**

| 토큰 | 값 | 용도 |
|---|---|---|
| `--jr-dur-fast` | `120ms` | 버튼 누름·칩 선택 |
| `--jr-dur-base` | `180ms` | 배너·대화상자 등장 |
| `--jr-dur-toast-in` | `180ms` | 토스트 등장 |
| `--jr-dur-toast-out` | `200ms` | 토스트 소멸 |
| `--jr-ease` | `cubic-bezier(0.2, 0, 0, 1)` | 전부 공통 |

토스트 **표시 시간 3초는 기획 확정값**입니다(화면설계 §0-2). 바꾸지 마십시오. 위 등장·소멸 시간은 그 3초에 **포함**됩니다.

**`prefers-reduced-motion` 대응 (필수)**

```css
@media (prefers-reduced-motion: reduce) {
  *:not(#jr-unsupported), *:not(#jr-unsupported)::before, *:not(#jr-unsupported)::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

- 위치 이동(`translate`)에 의존하는 등장 연출을 만들지 마십시오. 감속 설정에서 요소가 **즉시 나타나도 의미가 유지되어야** 합니다.
- **`#jr-unsupported` 는 이 리셋에서 반드시 제외합니다.** 그 요소의 `animation` 은 연출이 아니라 표시 지연 장치입니다(§3-3). 함께 꺼 버리면 정상 부팅 때마다 오류 문구가 번쩍입니다.

## 3. 파트장이 이미 확정한 설계 판단 (실무자가 다시 정하지 않습니다)

기획서 §8-3 이 ③ 에 넘긴 항목 중, **두 실무자에게 걸쳐 있어 한쪽이 정하면 어긋나는 것**을 파트장이 먼저 닫았습니다.

### 3-1. INT-04 카테고리 미선택 안내 — **중립 안내로 표시** (오류 강조 아님)

- 문구 `카테고리를 선택해 주세요.` (`E-112`), 표시 시점(미선택 동안 상시)은 기획 확정.
- **③ 결정: 중립 안내.** `--jr-text-muted` + 정보 아이콘. **`--jr-danger` 를 쓰지 않습니다.**
- 사유: 이 문구는 추가 모드 진입 **직후부터** 떠 있습니다(INT-04). 아직 아무 것도 하지 않은 사용자에게 붉은 오류를 먼저 보여 주는 것은 사용자를 탓하는 것이고, 구조설계 §7-0 문구 원칙 4("사용자를 탓하지 않습니다")와 충돌합니다. 또 이 화면의 진짜 오류(E-101~E-111)와 색이 같으면 **실제 오류의 신호가 죽습니다.**
- 다만 자리는 다른 I 슬롯과 **동일한 규격**(같은 위치·같은 높이·같은 아이콘 크기)으로 잡아 레이아웃이 흔들리지 않게 하십시오.

### 3-2. 비율 막대의 0% 항목 — **최소 채움 6px**

- 구조설계 §4-3-2: `percent` 가 0 인 항목이 실제로 발생하며(총액 100만 원 중 3,000원 = 0.3%) **숨기지 않습니다.**
- **③ 결정**: 막대 높이 **10px**, `border-radius: 999px`, 트랙에 `1px solid var(--jr-border)`.
  채움은 `width: {percent}%` 이되 **`min-width: 6px`** 를 함께 겁니다. `max()` 함수 대신 `min-width` 를 쓰는 이유는 구형 브라우저에서도 동일하게 동작하기 때문입니다.
- 결과: 0% 항목도 6px 채움이 보이고, 금액·비율 텍스트(`3,000원 (0%)`)가 정확한 값을 함께 말합니다 — **색·길이만으로 정보를 전달하지 않습니다.**
- `미분류(삭제된 카테고리)` 항목은 `--jr-bar-deleted` 채움이며 **항상 마지막**입니다(INT-07). UI 는 재정렬하지 않습니다.

### 3-3. `#jr-unsupported` — **3초 지연 노출** (CSS 만으로)

INT-14 는 이 요소가 HTML 에 미리 들어 있고 부팅 성공 시 `boot.js` 가 제거한다고만 정했습니다. 그대로 **기본 노출**로 만들면 **정상 부팅에서도 매번 "이 브라우저에서는 앱을 사용할 수 없습니다" 가 번쩍입니다.**

- **③ 결정**: `#jr-unsupported` 는 `opacity: 0`, `animation: jr-reveal 0s linear 3s forwards` 로 **3초 뒤에 나타납니다.**
- 정상 부팅: `boot.js` 가 3초보다 훨씬 전에 요소를 제거 → 사용자는 아무것도 보지 못합니다.
- 자바스크립트가 아예 죽은 경우: 3초 뒤 문구가 뜹니다. **JS 없이 동작해야 하므로 CSS 애니메이션이 유일한 수단입니다.**
- 이 요소는 `prefers-reduced-motion` 리셋에서 **제외**합니다(§2-7).
- `questions.md` **Q-015** 로 ②·④ 에 통지했습니다. ④ 실측 대상이기도 합니다.

### 3-4. 부팅 이전 3요소의 겹침 순서

| 요소 | 규칙 |
|---|---|
| `<noscript>` | 문서 최상단, 페이지 전체를 덮는 블록. JS 가 꺼진 경우만 브라우저가 표시 |
| `#jr-unsupported` | 페이지 전체를 덮는 블록. 3초 지연 노출(§3-3). z-index `60` — 앱 UI보다 위 |
| `#jr-loading` | 화면 중앙 정렬, **텍스트 `불러오는 중` 만.** 스피너·마크·아이콘 금지(화면설계 S-01 로딩 상태 확정: "텍스트만 표시"). z-index `10` |

세 요소 모두 **브랜드 마크를 넣지 않습니다.** 화면설계가 로딩 상태를 "텍스트만"으로 확정했습니다.

### 3-5. 포커스 순서 — 화면설계 표에 빠진 요소의 자리 (③ 확정)

화면설계의 포커스 순서표는 INT-01·INT-09·INT-10 이 추가한 요소를 반영하지 못했습니다. `questions.md` **Q-016** 으로 ② 확인을 요청했고, 그 답이 오기 전까지 아래를 적용합니다.

| 화면 | ③ 확정 순서 |
|---|---|
| S-01 | (배너 있으면) **배너 `닫기`** → 이전 달 → 다음 달 → 지출 추가 → 기록 행(위→아래) → 탭바(홈→통계→설정) |
| S-02 | (배너 있으면) **배너 `닫기`** → 취소 → 날짜 → 금액 → 카테고리 칩(그룹 1개 정지점, 내부는 좌우 방향키) → 메모 → 저장 → (수정 모드) 이 기록 삭제 |
| S-03 | (배너 있으면) **배너 `닫기`** → 이전 달 → 다음 달 → 탭바. 막대 목록은 포커스 받지 않음 |
| S-04 | (배너 있으면) **배너 `닫기`** → 카테고리 행들(각 행: 이름변경 → 삭제) → 새 카테고리 입력란 → 추가 → 내보내기 → **(대체 영역 노출 시) 텍스트 영역 → `전체 선택`** → 가져오기 → 전체 삭제 → 탭바 |

- **진입 시 초기 포커스**는 화면설계 확정값 그대로입니다(S-01·S-03 = `이전 달`, S-02 = 날짜, S-04 = 카테고리 첫 행). 배너 `닫기` 는 탭 순서상 앞에 있을 뿐 초기 포커스를 가져가지 않습니다.
- S-04 초기 포커스의 "첫 번째 행"은 행 자체가 조작 요소가 아니므로 **첫 행의 `이름변경` 버튼**으로 확정합니다.
- **E-307 읽기 전용 모드에서 S-04 카테고리 목록이 비므로**(INT-09) 초기 포커스 대상이 없습니다. 이때 초기 포커스는 `카테고리 관리` 구역 제목(`tabindex="-1"`)입니다.

### 3-6. 토스트 기준선 — S-02 에는 탭바가 없습니다

화면설계는 토스트를 "탭바 위에 겹침"으로 정의했으나 S-02 에는 탭바가 없습니다. **③ 확정**: 토스트 하단 여백 = `var(--jr-tabbar-h) + 8px + env(safe-area-inset-bottom)`. S-02 에서는 `--jr-tabbar-h: 0` 이므로 자연히 하단 8px + 안전영역이 됩니다. `questions.md` **Q-017** 로 통지.

### 3-7. E-307 · E-411 차단형 배너

- 닫기 버튼을 **만들지 않습니다**(구조설계 §7-8).
- 배경 `--jr-banner-block-bg`, 왼쪽 4px 세로 강조선 `--jr-danger`, 차단 아이콘(다른 두 종류와 모양이 다른 것).
- E-307 에서는 S-01·S-03 의 목록·막대 영역이 비고 **빈 상태 문구도 표시하지 않습니다**(INT-09). 그 자리에 자체 판단으로 안내 문구를 채워 넣지 마십시오 — 기록할 수 없는 상태에서 기록을 권하는 것이 거짓 안내라서 ② 가 의도적으로 비운 자리입니다.

## 5. `brand-designer` 배정

**산출 파일: `ai-team/apps/2026-08-11/docs/디자인-브랜드.md`** (이 파일에만 씁니다)

### 5-1. 전제 — 이 앱은 스토어에 올라가지 않을 수 있습니다

`file://` 로 여는 단일 정적 페이지이며, 배포 경로는 아직 확정되지 않았습니다. 그래도 스토어 스크린샷 구성안을 만드는 이유는 ⑥ 출시운영본부가 그 자료를 받기 때문입니다. **다만 실제 스토어 등록을 전제로 단정하지 마십시오.**

### 5-2. 만들 것

| # | 항목 | 요구 |
|---|---|---|
| 1 | **앱 아이콘 SVG** | `viewBox="0 0 1024 1024"` 마스터 1개. **인라인 SVG 코드 전문**을 문서에 넣으십시오(파일이 아니라 코드). 색은 `--jr-brand` `#0B6B5B` + `#FFFFFF` **2색까지.** 그라디언트·그림자·필터 금지(`file://` 렌더 편차) |
| 2 | **세이프존** | 원형·둥근사각 마스크에 잘리지 않도록 중앙 **80%** 안에 핵심 도형 배치. 잘림 시뮬레이션 근거를 적으십시오 |
| 3 | **파비콘 SVG** | 16px·32px 에서 형태가 무너지지 않도록 **단순화한 별도 버전.** 마스터 아이콘을 그대로 줄이지 마십시오 |
| 4 | **파비콘 삽입 문자열** | `<link rel="icon" href="data:image/svg+xml,…">` — **URL 인코딩까지 끝낸 한 줄**을 그대로 복사할 수 있게. `#` 은 `%23` 으로 인코딩해야 합니다(안 하면 조각 식별자로 잘립니다) |
| 5 | **파비콘 폴백 메모** | `data:` URI 파비콘이 `file://` 에서 무시되는 브라우저가 있을 수 있습니다. 같은 폴더 `assets/favicon.svg` 참조 방식도 함께 제시하고, **어느 쪽이 되는지는 ④ 실측 항목으로 남기십시오**(단정 금지) |
| 6 | **아이콘 대비 검증** | 아이콘의 전경 대 배경 대비비를 §7 공식으로 **계산**해 적으십시오. 3:1 이상 |
| 7 | **스토어 스크린샷 구성안** | 4~5장. 각 장: 어느 화면(S-01~S-04) · 무엇이 보이는가 · 캡션 문안 **초안** · 왜 이 순서인가. 캡션 확정은 ⑥/② 소관이므로 **초안**임을 명기 |
| 8 | **더미 데이터 세트** | 스크린샷에 넣을 가상의 지출 기록 8~12건(날짜·금액·카테고리·메모). 기본 카테고리 8종 안에서만. 금액은 현실적인 원 단위 정수 |

### 5-3. 아이콘 개념 방향 (파트장 지침 — 안을 좁힙니다)

| 원칙 | 이유 |
|---|---|

## 7. 대비비 계산식 (양쪽 공통 — 이 식으로만 계산)

WCAG 2.1 상대휘도. **눈으로 어림한 값은 반려 사유입니다.**

```
1) 각 채널 값을 0~1 로 정규화: c = v / 255
2) 선형화: c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ^ 2.4
3) 상대휘도 L = 0.2126*R + 0.7152*G + 0.0722*B
4) 대비비 = (밝은 쪽 L + 0.05) / (어두운 쪽 L + 0.05)
```

**검산용 기준점** — 본인 계산이 아래와 다르면 계산이 틀린 것입니다.

| 조합 | 정답 |
|---|---|
| `#000000` 대 `#FFFFFF` | 21.00:1 |
| `#16191D` 대 `#FFFFFF` | 17.63:1 |
| `#5A626B` 대 `#FFFFFF` | 6.19:1 |
| `#0B6B5B` 대 `#FFFFFF` | 6.43:1 |

문서에는 **소수점 둘째 자리까지** 적고, 기준(4.5 / 3)과 판정(✅/❌)을 함께 적으십시오.
