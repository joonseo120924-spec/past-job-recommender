### 되돌리지 않은 이유

Q-002·Q-003 을 반영해 재채점하면 B 82점 · A 84점으로 **역전 가능성이 실재**합니다(B 차별점 24→20, 사용자 가치 24→21 / A 차별점 19→21). 그럼에도 되돌리지 않는 근거 3가지입니다.

1. **지적은 점수 강도의 문제이지 후보 적합성의 문제가 아닙니다.** B 가 이 환경 제약과 충돌하는 지점은 재검증해도 없습니다(기술 제약 20/20 유효). 은행 연동이 설계에 없다는 것은 사실이고, 그 사실 자체는 조사 표본 크기와 무관합니다.
2. **대안 1순위 A 는 정면 상위호환 경쟁자가 조사로 확인되었습니다.** Loop Habit Tracker — 760만 다운로드, 4.72/5, 완전 무료·오프라인·오픈소스·광고 0·결제 0(`전략-경쟁.md:12-16`). B 의 약점은 "무광고 경쟁자가 없다는 것을 확인하지 못했다"는 **미확인**이고, A 의 약점은 "이미 있다는 것이 확인된" **확정 사실**입니다. 불확실성의 방향이 B 에 유리합니다.
3. **되돌림 비용이 얻는 것보다 큽니다.** 재조사(무광고·크로스플랫폼 가계부 앱 존재 여부)는 반나절 이상 소모하는데, A·B 는 4일 완성 가능성(21 vs 22)과 기술 제약 충족(20 vs 19)이 사실상 동일해 **되돌림으로 얻는 것은 "더 정확한 1위"이지 "완성 가능한 앱"이 아닙니다.** `master-doctrine.md:6` "멈추는 것도 비용이다".

## 2. MVP 범위 확정 (② 파트장 결정 — 이 표 밖의 것은 만들지 않습니다)

### 앱 정보

| 항목 | 값 |
|---|---|
| 앱 이름(가칭) | **정레** — ① 이 제안한 가칭을 유지합니다. 이름 확정은 ③ 디자인본부(브랜드) 영역이므로 ② 가 선점하지 않습니다 |
| 한 줄 정의 | 로그인 없이 기기 안에만 저장되는 수기 입력형 지출 기록 · 카테고리별 통계 앱 |
| 실행 방식 | 브라우저에서 `index.html` 을 `file://` 로 직접 열기. 서버 없음, 설치 없음, 네트워크 요청 0건 |
| 통화 | 원(KRW) 고정. **정수만 취급, 소수점 없음** (부동소수점 누적 오차 원천 차단) |
| 날짜 | 로컬 시간 기준 `YYYY-MM-DD` **문자열**로 저장. `Date` 객체를 직렬화하지 않습니다(타임존 이동 시 날짜가 하루 밀리는 사고 방지) |

### 기능 목록 — v1 (9개, 전부 필수)

| ID | 기능 | 한 줄 정의 |
|---|---|---|
| F-01 | 지출 추가 | 날짜·금액·카테고리·메모를 입력해 기록 1건 생성 |
| F-02 | 지출 수정 | 기존 기록의 4개 필드를 전부 수정 가능 |
| F-03 | 지출 삭제 | 기록 1건 삭제. 확인 1단계 거침 |
| F-04 | 목록 조회 | 선택된 월의 기록을 날짜 내림차순(같은 날짜면 생성 역순)으로 나열 |
| F-05 | 월 이동 | 이전 달 / 다음 달로 조회 대상 월 변경 |
| F-06 | 통계 | 선택된 월의 총합 + 카테고리별 합계·비율을 가로 막대 1종으로 표시 |
| F-07 | 카테고리 관리 | 기본 8종 제공 + 추가·이름변경·삭제 |
| F-08 | 내보내기 / 가져오기 | 전체 데이터를 JSON 파일로 저장 / 불러오기 (**기기 변경 시 유일한 백업 수단이므로 v1 필수**) |
| F-09 | 전체 삭제 | 모든 기록·카테고리를 초기화. 확인 2단계 거침 |

### v2 항목 (기록만 합니다 — **설계하지 않습니다**)

회원·로그인·계정, 클라우드 동기화, 결제·구독·광고, 수입 기록, 예산 목표·초과 알림, 푸시 알림, 다중 통화·환율, 반복 지출 자동 등록, 기록 검색, 태그, 첨부 이미지(영수증), 자동 카테고리 분류, CSV 형식 입출력, 연간 통계, 다크 모드.

> **회원·결제는 MVP 범위에 없으므로 화면·데이터·API·예외 어디에도 등장시키지 마십시오.** 로그인 화면, 사용자 ID 필드, 결제 상태 플래그, 권한 검사 로직 전부 금지입니다. 없는 것을 설계하지 않습니다.
>
> CSV 를 v2 로 미룬 이유: 쉼표·따옴표·줄바꿈 이스케이프 처리와 인코딩(BOM/EUC-KR) 분기가 필요해 JSON 대비 구현·검증 비용이 큽니다. v1 백업 목적에는 JSON 으로 충분합니다.

## 3. 공유 계약 (양 실무자가 **그대로** 사용 — 임의 변경 금지)

두 분은 병렬로 작업하므로 서로의 산출물을 볼 수 없습니다. 아래 식별자와 값은 제가 확정해 양쪽에 동일하게 전달하는 **계약**입니다. 이것이 어긋나면 두 산출물을 합칠 수 없습니다. 계약에 문제가 있으면 **고치지 말고** `ai-team/questions.md` 에 Q 를 남기고 계약대로 진행하십시오.

### 3-1. 화면 ID (4개 — 이 외의 화면을 만들지 않습니다)

| ID | 화면 | 역할 |
|---|---|---|
| S-01 | 홈 | 선택된 월의 총합 + 기록 목록. 앱 진입 시 첫 화면 |
| S-02 | 입력 | 지출 추가 / 수정 겸용 |
| S-03 | 통계 | 선택된 월의 카테고리별 합계·비율 |
| S-04 | 설정 | 카테고리 관리 · 내보내기/가져오기 · 전체 삭제 |

### 3-2. 데이터 필드명 (양쪽 동일 표기)

- 지출 기록: `id` · `date` · `amount` · `categoryId` · `memo` · `createdAt`
- 카테고리: `id` · `name` · `order` · `isDefault`

### 3-3. 기본 카테고리 8종 (순서 그대로)

`식비` · `교통` · `주거/통신` · `생활용품` · `의료/건강` · `문화/여가` · `의류/미용` · `기타`

### 3-4. 입력 제약 (양쪽 동일 — UX 는 안내 문구에, SA 는 검증 로직에 사용)

| 필드 | 제약 |
|---|---|
| `amount` | 정수. 최소 1, 최대 999,999,999. 소수점·음수·0 불가 |
| `date` | `YYYY-MM-DD`. 최소 `2000-01-01`, 최대 오늘로부터 1년 뒤 |
| `memo` | 0~100자. 공백만 입력 시 빈 문자열로 저장. 이모지 허용 |
| 카테고리 `name` | 1~12자. 공백만 불가. 같은 이름 중복 불가 |
| 카테고리 개수 | 최대 20개 |

### 3-5. 오류 표시 슬롯 3종 (SA 가 정의한 E-코드가 화면 어디에 뜨는지의 계약)

| 슬롯 | 위치 | 지속 | 용도 |
|---|---|---|---|
| **T** (토스트) | 화면 하단 | 3초 후 자동 소멸 | 작업 성공/실패 알림. 사용자가 되돌릴 필요 없는 것 |
| **I** (인라인) | 해당 입력 필드 바로 아래 | 입력이 유효해질 때까지 유지 | 입력값 검증 실패 |
| **B** (배너) | 화면 최상단 고정 | 사용자가 닫기 전까지 유지 | 저장소 차단·용량 초과·데이터 손상 등 앱 전체에 영향을 주는 상태 |

### 3-6. 전역 네임스페이스

전역 객체 **`JR`** 하나만 사용합니다. 하위 모듈: `JR.store` (localStorage 입출력) · `JR.model` (기록·카테고리 CRUD) · `JR.stats` (집계) · `JR.io` (내보내기/가져오기) · `JR.err` (E-코드·문구) · `JR.ui` (화면 렌더 — ④ 개발 배정 영역, 인터페이스만 정의).

### 3-7. 실행 환경 제약 (양쪽 공통 — 설계 전 반드시 대입)

- `file://` 직접 실행. **Service Worker 사용 불가**(등록 자체가 안 됨), **IndexedDB 사용 불가**(Chromium 이 SecurityError 로 차단)
- 저장소는 **localStorage 단일**. 상한 약 5MB
- 빌드 도구·번들러·트랜스파일러 없음 → **ES5~ES2015 수준의 소스를 그대로 브라우저가 읽습니다.** import/export 모듈 문법도 `file://` 에서 CORS 로 막히므로 사용 금지. `<script>` 태그 나열 방식
- 외부 네트워크 요청 0건. CDN·웹폰트·외부 아이콘·분석 스크립트 전부 금지
- 외부 라이브러리 0개. 차트 라이브러리·날짜 라이브러리·프레임워크 전부 금지

### 4-1. `ux-designer` — 화면설계

5. **화면 전환 흐름**을 전환표로 정리하십시오. 4개 화면 간 어느 요소를 누르면 어디로 가는지, 뒤로 가기가 어떻게 동작하는지
6. **F-08 가져오기의 확인 흐름**을 반드시 정의하십시오 — 가져오기는 기존 데이터를 덮어쓰는 파괴적 동작입니다. 사용자가 무엇을 잃는지 명시적으로 알리는 확인 단계가 필요합니다

8. 오류가 뜨는 위치를 §3-5 슬롯 코드(T/I/B)로 표기하십시오. 예: "금액 미입력 → I 슬롯". **E-코드 자체와 오류 문구는 `system-architect` 가 씁니다** — 중복 작성하지 마십시오

**반드시 답이 나와야 하는 질문 (개발자가 물을 것)**

- 입력 화면에서 카테고리를 고르지 않으면 저장 버튼이 눌리는가?
- 금액 입력란에 문자를 치면 어떻게 되는가 — 막는가, 입력은 되되 저장에서 막는가?
- 기록을 수정하려면 목록에서 무엇을 누르는가? 삭제는 어디서 하는가?
- 카테고리를 삭제했는데 그 카테고리를 쓰는 기록이 30건 남아있으면 화면에 무엇이 보이는가?
- 통계 화면에서 그 달 기록이 0건이면 무엇이 보이는가?
- 뒤로 가기(브라우저 뒤로 버튼 포함)를 누르면 어디로 가는가?

### 4-2. `system-architect` — 구조설계

**산출 파일: `ai-team/apps/2026-08-11/docs/기획-구조설계.md`**
(에이전트 정의에는 `docs/기획-구조설계.md` 로만 적혀 있습니다. **반드시 위 전체 경로**에 쓰십시오 — 앱 폴더 접두사 누락은 알려진 결함입니다(감사 중대-3 / 드리프트 6).)

**해야 할 것**

1. **데이터 구조** — 지출 기록·카테고리·앱 설정(선택된 월 등)의 필드명·타입·제약·기본값을 표로. §3-2·§3-4 계약을 그대로 사용하십시오
2. **localStorage 키 설계** — 키 이름, 저장 단위(전체를 한 키에 넣을지 분할할지), **스키마 버전 필드**(향후 마이그레이션용), JSON 직렬화 형태를 실제 예시와 함께
3. **모듈 인터페이스** — §3-6 네임스페이스 아래 모든 공개 함수의 **정확한 시그니처와 반환값**. 두 개발자가 서로의 코드를 못 본다는 전제로 쓰십시오. 반환값은 성공/실패를 어떻게 구분하는지까지(예: `{ok: true, data}` / `{ok: false, code: 'E-0xx'}`)
4. **집계 로직** — 월별 총합, 카테고리별 합계·비율 계산 방식. **비율의 반올림 처리와 합이 100%가 안 되는 경우**를 어떻게 다루는지 명시(정수 퍼센트 반올림 시 합이 99% 또는 101%가 되는 문제는 실제로 발생합니다)
5. **정렬 규칙** — 날짜 내림차순, 같은 날짜 내 순서를 무엇으로 결정하는지 결정적으로(비결정적 정렬은 새로고침마다 목록 순서가 바뀌는 버그가 됩니다)
6. **F-08 JSON 스키마** — 내보내기 파일의 정확한 구조, 파일명 규칙, 가져오기 시 검증 절차(**남이 만든 파일·손상된 파일·다른 앱의 JSON 이 들어올 수 있다는 전제**)
7. **E-코드 전체** — 에이전트 정의의 필수 항목을 **전부** 다루십시오: 빈값 · 1000자 입력 · 이모지 · 경계값 · 저장소 차단 · 용량 초과 · 데이터 손상 · 권한 거부 · 미지원 브라우저/기기 · 중복 클릭 · 새로고침 · 백그라운드 전환. 각 E-코드에는 **사용자가 실제로 보게 될 한국어 문구**와 §3-5 표시 슬롯(T/I/B)을 반드시 붙이십시오

**이 환경에서 반드시 다뤄야 하는 예외 (누락 시 반려)**

| 상황 | 왜 필수인가 |
|---|---|
| localStorage 자체가 차단됨 | `file://` + 브라우저 프라이버시 설정 조합에서 실제로 발생. 메모리 폴백 + B 슬롯 배너 필수 (C-4) |
| localStorage 용량 초과(`QuotaExceededError`) | 약 5MB 상한. 저장 실패 시 **기존 데이터를 훼손하지 않고** 실패해야 함 |
| 저장된 JSON 이 파싱 불가(손상) | 사용자가 개발자도구로 건드렸거나 저장 중 중단된 경우. **전체 초기화로 도망가지 말고** 복구 가능 범위를 정의하십시오 |
| 가져온 파일이 이 앱의 JSON 이 아님 | 검증 실패 시 **기존 데이터는 그대로 두고** 거부해야 함 |
| 저장 버튼 중복 클릭 | 기록이 2건 생성되는 사고. 어떻게 막는지 |
| 새로고침 / 브라우저 뒤로 가기 | 입력 중이던 내용은 어떻게 되는가. 되살릴 것인지 버릴 것인지 **결정**하십시오 |
| 파일 다운로드 API 가 `file://` 에서 막히는 경우 | F-08 내보내기가 동작하지 않을 수 있음. 대체 경로를 정의하십시오 |
| 브라우저가 필요한 API 를 지원하지 않음 | 어떤 API 를 어떻게 감지하고, 감지되면 무엇을 보여주는지 |

**하지 말 것**

- **"에러 처리한다" 같은 서술 금지.** 무슨 코드로, 무슨 문구로, 어떤 상태가 되는지 쓰십시오
- Service Worker · IndexedDB · 외부 라이브러리 · ES 모듈 문법을 설계에 넣지 마십시오 (§3-7)
- 서버 API·인증 토큰·사용자 ID·결제 상태를 설계에 넣지 마십시오. v2 항목입니다
- 화면 배치·버튼 위치·화면 전환을 정의하지 마십시오 — `ux-designer` 영역입니다. 여러분은 **E-코드 문구**를 쓰고, 그 문구가 어디 뜨는지는 슬롯 코드(T/I/B)로만 지정하십시오
- 모호한 표현 금지: "적절히", "알아서", "등등", "필요시"
