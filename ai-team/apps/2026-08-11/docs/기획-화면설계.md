## 0. 공통 규칙 (4개 화면에 공통 적용)

### 0-1. 전역 상태 — "선택된 월"

- S-01(홈)과 S-03(통계)은 **같은 "선택된 월" 값을 공유**합니다. 한쪽에서 월을 이동하면 다른 화면에도 그대로 반영됩니다(별개의 월 상태를 화면마다 따로 갖지 않습니다).
- 최초 실행 시 기본값 = 오늘이 속한 월.
- 앱을 껐다 켜도(새로고침 포함) 마지막으로 조회하던 월을 유지합니다. (분배안 §4-2 "앱 설정(선택된 월 등)"에 대응하는 UX 결정입니다. 실제 저장 여부·필드명은 `system-architect` 확인 사항입니다.)
- 월 이동 가능 범위: `date` 최소값(`2000-01-01`)이 속한 월 ~ `date` 최대값(오늘로부터 1년 뒤)이 속한 월. 이 범위를 벗어나는 이동 버튼은 비활성화됩니다(각 화면 표에 명시).

### 0-2. 공통 UI 요소

| 요소 | 위치 | 노출 화면 | 설명 |
|---|---|---|---|
| 하단 탭바 | 화면 최하단 고정 | S-01·S-03·S-04 (S-02 에는 없음) | 탭 3개: "홈" · "통계" · "설정". 현재 화면에 해당하는 탭은 시각적으로 구분 표시(선택 상태). 탭 전환은 브라우저 히스토리에 기록하지 않음(§ 뒤로가기 규칙 참조) |
| 배너 (**B** 슬롯) | 화면 최상단, 탭바보다 위, 스크롤에 영향받지 않고 고정 | 4개 화면 공통 | 저장소 차단·용량 초과·데이터 손상 등 앱 전체에 영향을 주는 상태를 사용자가 닫기 전까지 계속 보여줌. 닫기 버튼("닫기") 존재 — 닫아도 원인이 해소된 것은 아니므로 문제가 남아있는 한 다음 화면 진입 시 다시 노출됨. 문구는 `system-architect` 정의 |
| 토스트 (**T** 슬롯) | 화면 하단, 탭바 위에 겹쳐 표시 | 4개 화면 공통 | 3초 후 자동 소멸. 동시에 여러 건 발생 시 마지막 것으로 교체(누적 쌓지 않음) |
| 인라인 오류 (**I** 슬롯) | 해당 입력 필드 바로 아래 | 입력 요소가 있는 화면(S-02, S-04 카테고리 입력) | 입력값이 유효해지는 순간 사라짐 |

### 0-3. 접근성 공통 원칙 (③ 디자인본부가 구체 수치로 검증)

- 모든 버튼·입력·탭 요소는 **한 손 엄지로 오조작 없이 누를 수 있는 터치 영역**을 확보해야 합니다. 인접한 상호작용 요소(예: "삭제"와 "이름변경") 사이에는 오탭을 막을 수 있는 간격이 필요합니다.
- **포커스 순서는 화면에 보이는 시각적 순서와 일치**해야 합니다. 각 화면 진입 시 첫 포커스 위치는 화면별 표 하단에 명시합니다.
- **모든 동작은 키보드만으로 완료 가능**해야 합니다: Tab/Shift+Tab 으로 이동, Enter 또는 Space 로 활성화.
- 확인 대화상자(모달)가 열리면 포커스가 대화상자 내부(기본 취소 버튼 등 안전한 선택지)로 이동하고, **Esc 키는 "취소"와 동일하게 동작**합니다. 대화상자가 닫히면 포커스는 이를 연 버튼으로 되돌아옵니다.
- 카테고리 칩(S-02)처럼 같은 그룹 안에서 하나만 고르는 요소는 좌우 방향키로 이동, Space/Enter 로 선택 가능해야 합니다(라디오 그룹과 동일한 조작 방식).
- 아이콘만 있는 버튼은 두지 않습니다. 모든 버튼은 텍스트 라벨을 갖거나, 텍스트를 대신할 스크린리더용 대체 텍스트를 가져야 합니다(이 문서의 "라벨" 열이 그 텍스트입니다).

### 0-4. 표기 규칙

- 금액: 천 단위 구분 쉼표 + "원" 접미사. 예: `1,234,000원`. 0원은 `0원`으로 표기.
- 날짜(목록 등에서): 선택된 월이 이미 화면 상단에 표시되어 있으므로 목록 행에서는 "일"만 표기(예: `15일`). 통계·설정 등 월 맥락이 없는 곳에는 전체 날짜(`YYYY-MM-DD`)를 씁니다.
- 카테고리를 표시해야 하는데 참조된 카테고리를 찾을 수 없는 경우(삭제된 카테고리를 쓰던 기존 기록 등) — 공통 대체 라벨: **`미분류(삭제된 카테고리)`**. 이 라벨은 선택 불가능한 표시 전용 텍스트이며 실제 카테고리 목록에는 나타나지 않습니다.

- 하단 탭바 `설정` 누름 → S-04

### 상태별 변형

**첫 실행 (전체 기록 0건)**
- 목록 영역에 총합 대신 안내 문구만 표시.
- 빈 상태 문구: `아직 기록이 없어요` (제목) / `첫 지출을 기록해 보세요.` (본문)
- `+ 지출 추가` 버튼은 그대로 활성 상태로 강조 노출.

**해당 월만 기록 0건 (다른 달에는 기록 존재)**
- 빈 상태 문구: `이 달에는 기록이 없습니다.`
- 총합 표시는 `0원` 그대로 유지(문구로 대체하지 않음).

**기록이 많을 때(수백 건, 선택된 월 또는 누적 기준)**
- 목록은 세로 스크롤 단일 컬럼. 페이지 나누기·더보기 버튼 없음 — 선택된 월의 전체 기록을 한 번에 나열.
- 메모가 길면 목록 행 안에서 한 줄로 줄이고 넘치는 부분은 말줄임(잘림) 처리. 전체 메모는 해당 행을 눌러 S-02 에서 확인.
- 카테고리 20개, 기록 수백 건이어도 정렬·필터 UI를 추가로 두지 않습니다(F-04 범위: 날짜 내림차순 고정 나열만).

**로딩 상태 (앱 최초 진입, localStorage 읽는 동안)**
- 화면 중앙에 `불러오는 중` 텍스트만 표시. 탭바·버튼 등 상호작용 요소는 이 순간 렌더링하지 않음(읽기가 끝난 뒤 정상 화면으로 교체).

**오류 상태 (저장소 차단 / 데이터 손상)**
- 화면 최상단 배너(B 슬롯)가 상시 노출된 채로, 그 아래는 다음 중 하나로 정상 렌더링됨:
  - 저장소 자체가 차단된 경우: 화면과 모든 기능(추가/수정/삭제)은 평소와 동일하게 동작(메모리 기준). 다만 새로고침 시 사라진다는 사실은 배너가 안내.
  - 저장 데이터가 손상되어 일부만 복구된 경우: 복구된 기록만으로 정상 화면 구성. 복구된 기록이 하나도 없으면 "첫 실행" 빈 상태와 동일한 화면을 배너와 함께 노출.

접근성: 첫 포커스는 `이전 달` 버튼. 포커스 순서 = 이전 달 → 월 표시(건너뜀, 포커스 불가) → 다음 달 → 지출 추가 → 기록 행(위에서 아래) → 하단 탭바(홈 → 통계 → 설정).

## 화면: 입력 (S-02)

지출 추가·수정 겸용 화면. 탭바 없음.

| 요소 | 라벨 | 동작 | 비활성 조건 |
|---|---|---|---|
| 상단 제목 | 추가 모드 `지출 추가` / 수정 모드 `지출 수정` | 표시 전용 | 해당 없음 |
| 취소 버튼 | `취소` | 값이 하나도 안 바뀌었으면 즉시 진입 전 화면(홈 또는 통계)으로 이동. 하나라도 바뀌었으면 확인 대화상자 노출 후 결정에 따름 | 없음(항상 눌림) |
| 날짜 필드 | `날짜` (안내: `2000-01-01 ~ (오늘로부터 1년 뒤) 사이 날짜만 입력할 수 있습니다.`) | 날짜 선택. 추가 모드 기본값 = 오늘, 수정 모드 기본값 = 해당 기록 값 | 입력 요소 자체는 항상 조작 가능. 범위를 벗어난 값을 넣으면 저장 시 I 슬롯 오류 |
| 금액 필드 | `금액` (플레이스홀더 `0`, 접미사 `원` 고정 표시, 안내: `1원 ~ 999,999,999원까지 입력할 수 있습니다.`) | 숫자만 입력. 입력하는 즉시 천 단위 쉼표 자동 표시. 최소 1 · 최대 999,999,999 | 입력란은 항상 조작 가능하나, **숫자가 아닌 문자(문자·소수점·기호 포함)는 입력되는 순간 걸러져 반영되지 않음**(입력 자체를 막음). 범위를 벗어난 숫자(0, 999,999,999 초과 등)는 입력은 되지만 저장 시 I 슬롯 오류 |
| 카테고리 선택 | `카테고리` (미선택 시 안내: `카테고리를 선택해 주세요.`) | 등록된 카테고리를 등록 순서대로 칩 버튼 목록으로 나열, 하나 탭하면 선택 표시(단일 선택). 추가 모드 기본값 = 미선택, 수정 모드 기본값 = 기존 값 선택됨 | 이미 선택된 칩을 다시 눌러도 선택 해제되지 않음(반드시 하나는 선택된 상태 유지). 등록된 카테고리가 0개면 이 영역 대신 "설정에서 카테고리를 먼저 추가해 주세요." 안내로 대체되고 저장 버튼은 비활성 |
| 메모 필드 | `메모 (선택)` (플레이스홀더 `메모를 남겨보세요`, 우측 하단 글자수 `0/100`) | 자유 입력. 100자 넘는 입력은 100자에서 끊김(입력 자체 제한). 공백만 입력 후 저장하면 빈 문자열로 저장됨 | 없음(항상 조작 가능, 별도 오류 없음) |
| 저장 버튼 | `저장` | 눌린 즉시 버튼을 비활성화해 중복 클릭을 막고 저장 처리. 성공 시 T 슬롯 토스트 `저장했습니다` 후 홈으로 복귀, 목록·총합 갱신 | 날짜 미입력 또는 범위 밖 **또는** 금액 미입력·0·범위 밖 **또는** 카테고리 미선택 **또는** 등록된 카테고리가 0개일 때 |
| 삭제 버튼(수정 모드에서만 노출) | `이 기록 삭제` | 확인 대화상자(1단계) 노출 → 확정 시 삭제, T 슬롯 토스트 `삭제했습니다` 후 홈으로 복귀 | 없음(수정 모드에서는 항상 눌림). 추가 모드에서는 버튼 자체가 화면에 없음 |

전환:
- `취소` 누름(변경 없음) → 진입 전 화면(S-01 또는 S-03)
- `취소` 누름(변경 있음) → 확인 대화상자 → `나가기` 누름 → 진입 전 화면 / `계속 입력` 누름 → S-02 유지
- `저장` 누름(성공) → S-01
- `이 기록 삭제` 누름 → 확인 대화상자 → `삭제` 누름 → S-01 / `취소` 누름 → S-02 유지

확인 대화상자 문구:
- 나가기 확인: `지금 나가면 입력한 내용이 사라집니다. 나갈까요?` — 버튼 `계속 입력` / `나가기`
- 기록 삭제 확인: `이 기록을 삭제할까요?` 부가설명 `삭제한 기록은 복구할 수 없습니다.` — 버튼 `취소` / `삭제`

빈 상태 문구: 해당 없음(이 화면은 항상 값이 채워진 폼이며, 등록된 카테고리 0개일 때만 위 카테고리 영역 대체 문구 `설정에서 카테고리를 먼저 추가해 주세요.` 노출)

접근성: 진입 시 첫 포커스는 **날짜 필드**. 포커스 순서 = 취소 → 날짜 → 금액 → 카테고리 칩(좌우 방향키로 그룹 내 이동) → 메모 → 저장 → (수정 모드에서만) 이 기록 삭제.

## 화면: 통계 (S-03)

| 요소 | 라벨 | 동작 | 비활성 조건 |
|---|---|---|---|
| 배너 (B 슬롯) | (system-architect 문구) | S-01 과 동일 규칙 | 해당 상태 아니면 미노출 |
| 이전 달 / 월 표시 / 다음 달 | S-01 과 동일 | 선택된 월 변경(S-01 과 상태 공유) | S-01 과 동일 규칙 |

| 카테고리별 막대 목록 | 카테고리명 + 가로 막대(비율) + 금액·비율 텍스트(예: `320,000원 (24%)`) | 표시 전용, 탭해도 다른 화면으로 이동하지 않음. 그 달에 합계가 0원을 초과하는 카테고리만, 금액 내림차순으로 나열. `미분류(삭제된 카테고리)` 항목도 동일 규칙으로 포함 | 해당 없음 |
| 하단 탭바 | `홈` / `통계` / `설정` | S-01 과 동일 | 없음 |

전환:
- 하단 탭바 `홈` 누름 → S-01
- 하단 탭바 `설정` 누름 → S-04
- `이전 달` / `다음 달` 누름 → S-03 유지, 선택된 월만 변경

빈 상태 문구: `이 달에는 기록이 없어 통계를 표시할 수 없습니다.` (막대 목록 영역 전체를 이 문구로 대체, 총합은 `0원 · 총 0건`으로 그대로 표시)

기록이 많을 때(카테고리 최대 20개 + 그중 다수가 그 달에 사용됨): 막대 목록은 세로 스크롤. 별도 접기/더보기 없이 전부 나열.

접근성: 첫 포커스는 `이전 달` 버튼. 막대 목록은 포커스를 받지 않는 정보 표시 영역(탭 불가 항목이므로 Tab 순서에서 건너뜀). 포커스 순서 = 이전 달 → 다음 달 → 하단 탭바.

## 화면: 설정 (S-04)

세 구역으로 구성된 단일 스크롤 화면(하위 화면 없음): **카테고리 관리** · **데이터 관리** · **데이터 초기화**.

| 요소 | 라벨 | 동작 | 비활성 조건 |
|---|---|---|---|
| 배너 (B 슬롯) | (system-architect 문구) | S-01 과 동일 규칙 | 해당 상태 아니면 미노출 |
| 구역 제목 | `카테고리 관리` | 표시 전용 | 해당 없음 |

| 편집 상태의 `취소` 버튼 | `취소` | 편집 취소, 행을 원래 이름으로 표시 상태 복귀 | 없음 |
| 행 내 `삭제` 버튼 | `삭제` | 확인 대화상자(해당 카테고리를 쓰는 기록 수에 따라 문구 2종 중 하나) → 확정 시 삭제, T 슬롯 토스트 `카테고리를 삭제했습니다` | 현재 등록된 카테고리가 1개뿐일 때(마지막 카테고리는 삭제 불가 — 최소 1개 유지) |
| 새 카테고리 입력란 | 플레이스홀더 `새 카테고리 이름` | 텍스트 입력 | 카테고리 총 개수가 이미 20개면 입력란과 아래 `추가` 버튼 모두 비활성, 대신 안내문 `카테고리는 최대 20개까지 만들 수 있습니다.` 노출 |
| `추가` 버튼 | `추가` | 새 카테고리 생성(등록 순서 맨 끝에 추가). 성공 시 T 슬롯 토스트 `카테고리를 추가했습니다`, 입력란 비움 | 입력값이 비어있음/공백만 **또는** 1~12자 범위 벗어남 **또는** 기존 카테고리와 이름 중복(이 경우 I 슬롯) **또는** 카테고리 총 개수 이미 20개 |
| 구역 제목 | `데이터 관리` | 표시 전용 | 해당 없음 |
| `내보내기` 버튼 | `내보내기` | 전체 데이터를 파일로 저장 시도. 성공 시 T 슬롯 토스트 `내보내기를 완료했습니다`. 파일 저장 방식 자체가 이 환경에서 동작하지 않으면 대체 영역(아래) 노출 | 내보내기/가져오기 처리가 진행 중인 동안(중복 실행 방지) |
| 내보내기 대체 영역 (파일 저장이 막힌 경우에만 노출) | 안내문 `파일 저장이 지원되지 않는 환경입니다. 아래 내용을 직접 복사해 보관하세요.` + 읽기전용 텍스트 영역(전체 JSON 내용) + `전체 선택` 버튼 | `전체 선택` 누르면 텍스트 영역 내용 전체 선택 상태로 전환(사용자가 바로 복사 가능) | 해당 파일 저장 실패 상황이 아니면 이 영역 자체가 없음 |
| `가져오기` 버튼 | `가져오기` | 파일 선택 창을 염(JSON 파일만). 파일 선택 후 형식이 이 앱의 데이터가 아니면 T 슬롯 오류로 종료(기존 데이터 유지, 대화상자 없이 끝). 형식이 올바르면 확인 대화상자(파괴적 동작 경고) 노출 | 내보내기/가져오기 처리가 진행 중인 동안(중복 실행 방지) |

| 가져오기 확인 대화상자의 `취소` 버튼 | `취소` | 대화상자만 닫음, 기존 데이터 그대로 유지 | 없음 |

| `전체 삭제` 버튼 | `전체 삭제` | 2단계 확인 대화상자 진행 → 최종 확정 시 모든 기록 삭제 + 카테고리를 기본 8종으로 재설정. 성공 시 T 슬롯 토스트 `모두 삭제했습니다`, 화면은 S-01 로 이동 | 없음(항상 눌림) |

- `전체 삭제` → 1단계 대화상자 → `다음` → 2단계 대화상자 → `모두 삭제` → S-01 / 각 단계 `취소` → S-04 유지
- 하단 탭바 `홈` 누름 → S-01 / `통계` 누름 → S-03

확인 대화상자 문구:
- 카테고리 삭제(사용 기록 없음): `'{카테고리명}' 카테고리를 삭제할까요?` — 버튼 `취소` / `삭제`
- 카테고리 삭제(사용 기록 {N}건 있음): `'{카테고리명}' 카테고리를 사용하는 기록이 {N}건 있습니다. 카테고리를 삭제해도 기록은 남지만, 해당 기록에서는 카테고리가 '미분류(삭제된 카테고리)'로 표시됩니다.` — 버튼 `취소` / `삭제`
- 가져오기(파괴적 동작 경고): `가져오기를 진행하면 현재 기기에 저장된 기록 {N}건과 카테고리 {M}개가 모두 사라지고, 선택한 파일의 데이터로 바뀝니다. 이 작업은 되돌릴 수 없습니다.` — 버튼 `취소` / `가져오기`
- 전체 삭제 1단계: `모든 기록과 카테고리를 삭제할까요? 삭제하면 되돌릴 수 없습니다.` — 버튼 `취소` / `다음`
- 전체 삭제 2단계(최종): `정말 삭제할까요? 마지막 확인입니다. 삭제 후에는 어떤 방법으로도 복구할 수 없습니다.` — 버튼 `취소` / `모두 삭제`

빈 상태 문구: 해당 없음(설정 화면은 카테고리가 최소 1개 이상 항상 존재하므로 목록이 완전히 비지 않음). 카테고리 20개 도달 시 안내문은 위 표에 명시.

카테고리가 많을 때(최대 20개): 카테고리 목록은 세로 스크롤. 별도 검색·정렬 UI 없음(등록 순서 고정).

접근성: 첫 포커스는 카테고리 목록의 첫 번째 행. 포커스 순서 = 카테고리 행들(위→아래, 각 행 내부는 이름변경 → 삭제) → 새 카테고리 입력란 → 추가 → 내보내기 → 가져오기 → 전체 삭제 → 하단 탭바.

## 반드시 답이 나와야 하는 질문 — 즉답 정리

- **카테고리를 고르지 않으면 저장 버튼이 눌리는가?** 눌리지 않습니다. S-02 `저장` 비활성 조건에 "카테고리 미선택" 포함.
- **금액 입력란에 문자를 치면?** 입력되지 않습니다(입력 시점에 걸러짐). 숫자만 반영되며, 범위(1~999,999,999) 위반은 입력은 되되 저장 시 I 슬롯 오류로 막습니다.
- **기록 수정은 어디서? 삭제는 어디서?** 홈(S-01) 목록에서 기록 행을 누르면 S-02(수정 모드)가 열립니다. 삭제는 그 S-02 화면 하단 `이 기록 삭제` 버튼입니다. 목록 자체에는 삭제 버튼이 없습니다.
- **카테고리를 삭제했는데 그 카테고리를 쓰는 기록이 30건 남아있으면?** 그 30건은 사라지지 않고 그대로 목록·통계에 남되, 카테고리 표시가 `미분류(삭제된 카테고리)`로 바뀝니다. 삭제 시도 시점에 대화상자가 먼저 그 사실(사용 기록 건수)을 알립니다.
- **통계 화면에서 그 달 기록이 0건이면?** 막대 목록 대신 `이 달에는 기록이 없어 통계를 표시할 수 없습니다.` 문구만 보이고, 총합은 `0원 · 총 0건`으로 표시됩니다.
- **뒤로 가기를 누르면 어디로 가는가?** 위 "뒤로가기 규칙" 표 참조. 핵심: S-02 밖에서는 앱을 벗어나고, S-02 안에서는 변경 여부에 따라 즉시 복귀하거나 확인을 거칩니다.

## 가정 및 확인 필요 사항 (통합 시 `product-planner` 확인 요청 — questions.md 는 실무자가 직접 남기지 않고 이 문서에 기록만 남깁니다)

1. "선택된 월"을 S-01·S-03 이 공유하고 재실행 후에도 유지된다는 것은 분배안 §4-2 힌트("앱 설정(선택된 월 등)")를 근거로 한 UX 설계 결정입니다. `system-architect` 의 데이터 구조 설계와 필드명이 이 전제를 충족하는지 통합 시 대조가 필요합니다.
2. "카테고리는 최소 1개를 항상 유지한다(마지막 카테고리 삭제 금지)"는 이 문서에서 새로 정한 화면 규칙입니다. 데이터 규칙(§5 경계표상 `system-architect` 영역)과 충돌하지 않는지 확인이 필요합니다.
3. 내보내기 대체 영역(파일 저장 API 가 막힌 경우 텍스트 영역으로 대체)은 `system-architect` 가 정의할 "대체 경로"의 UI 측 반영입니다. 대체 경로의 실제 동작 방식에 따라 이 영역의 문구·조작 흐름을 재조정해야 할 수 있습니다.
