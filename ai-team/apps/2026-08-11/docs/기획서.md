## 5. API 정의 (② 게이트 항목 4/5)

**정본: `docs/기획-구조설계.md` §5.** 모듈 6개(`JR.err`·`JR.store`·`JR.model`·`JR.stats`·`JR.io`·`JR.ui`)의 공개 함수 시그니처·인자·반환 형태가 전부 확정되어 있습니다.

핵심 계약:

- 반환 규약: 성공 `{ok:true, data:{...}}` / 실패 `{ok:false, code:'E-xxx', data:{...}}`
- **예외를 던지지 않습니다.** 모든 공개 함수는 내부 `try/catch`, 예상 못 한 예외는 `E-501`
- `{ok}` 로 감싸지 않는 함수는 **정확히 12개** — 순수 계산 9개(`today`·`minDate`·`maxDate`·`countChars`·`normName`·`shiftMonth`·`monthRange`·`allocatePercents`·`formatAmount`) + 상태 조회 3개(`store.mode`·`model.isReady`·`model.isNoticeDismissed`). **이 목록에 함수를 추가하지 마십시오**
- 스크립트 로드 순서 고정: `err → store → model → stats → io → ui → boot`
- 역방향 호출 허용은 1건뿐: `JR.model` 쓰기 성공 직후 `JR.stats.invalidate()` (존재 확인 후 호출)
- `JR.ui` 고정 함수: `toast` · `inline` · `banner` · `dismissBanner` + `lock` · `unlock` + **`show`(INT-15 로 필수화)**

## 7. 통합 확정 (INT) — **하위 문서보다 우선합니다**

두 문서를 맞대어 본 결과입니다. **구멍 3건(두 문서가 서로 어긋남) · 구멍 2건(문서 내부 자기모순) · 미정의 8건(어느 문서에도 답이 없음)** 을 찾아 전부 닫았습니다. 각 항목은 ④ 가 추가 질문 없이 구현할 수 있는 형태로 씁니다.

### 7-1. 어긋남을 닫은 것

#### INT-01 · S-02 에도 B 슬롯이 있습니다 (구조설계 Q-010 **기각**)

- **상황**: 구조설계 §7-7 은 "S-02 요소표에 배너 행이 없다"를 불일치로 보고, S-02 에서는 B 코드를 T 로 대체 표시하는 잠정 규칙을 세웠습니다.
- **재검토 결과**: 화면설계 §0-2 공통 규칙 표는 배너의 노출 화면을 **"4개 화면 공통"** 으로 이미 명시했습니다. S-02 요소표에 행이 없는 것은 공통 규칙에 이미 있어 반복하지 않은 것이며, 슬롯 자체는 존재합니다.
- **확정**: **S-02 에도 B 슬롯 배너를 그대로 표시합니다.** 위치는 화면 최상단(상단 제목·`취소` 버튼보다 위), 스크롤 무관 고정. 구조설계의 "T 로 대체" 규칙은 **채택하지 않습니다.**
- **사유**: E-202 문구는 3문장(`저장 공간이 가득 차 … 이전 기록은 그대로 있습니다. … 내보내기로 백업한 뒤 …`)이라 3초 후 사라지는 토스트로는 읽을 수 없습니다. 데이터 소실 가능성 고지는 사용자가 닫을 때까지 남아야 합니다(`team-rules.md:38` 의견 충돌 해결 ④ 보안·안정성 우선).

#### INT-07 · 통계에서 `미분류(삭제된 카테고리)` 는 **항상 마지막**

- **상황**: 화면설계 S-03 은 "미분류 항목도 동일 규칙(금액 내림차순)으로 포함", 구조설계 §4-3-1 은 "`__deleted__` 는 금액이 크더라도 항상 마지막".
- **확정**: **구조설계를 채택합니다.** `JR.stats.byCategory()` 가 반환한 `items` 배열 순서를 UI 가 **그대로** 그립니다. UI 는 재정렬하지 않습니다.
- **사유**: 정렬 책임이 두 곳에 있으면 어긋납니다. 사용자가 정상 카테고리를 먼저 보는 것이 맞습니다.

#### INT-06 · dangling 카테고리 라벨은 `미분류(삭제된 카테고리)` 하나

- **상황**: 구조설계 §2-7 항목1 은 `삭제된 카테고리`, 같은 문서 §5-4-4·§5-5·§7-7 은 `미분류(삭제된 카테고리)` — **구조설계 내부에서 두 값이 병존**합니다.
- **확정**: **`미분류(삭제된 카테고리)`** 단일. 구조설계 §2-7 항목1 의 값은 폐기합니다. `JR.model.getCategoryName()` 과 `StatItem.categoryName` 이 이 문자열을 반환하며, 이 라벨은 표시 전용이고 카테고리 선택 목록에 나타나지 않습니다.
- Q-007 · Q-009 **종결**.

### 7-2. 자기모순을 닫은 것

#### INT-02 · S-02 `저장` 버튼의 비활성 조건을 **축소**합니다

- **상황(화면설계 내부 모순)**: 금액 필드 행은 "범위를 벗어난 숫자는 입력은 되지만 **저장 시 I 슬롯 오류**"라고 쓰고, 같은 화면의 `저장` 버튼 비활성 조건에는 "금액 … 범위 밖"이 들어 있습니다. 버튼이 비활성이면 저장 시도 자체가 불가능하므로 두 서술은 동시에 성립할 수 없습니다. 이대로 두면 **E-103·E-104·E-105·E-106·E-107·E-109·E-110·E-111 여덟 개 코드가 영원히 도달하지 않는 죽은 코드**가 됩니다.
- **확정 — `저장` 버튼 비활성 조건은 아래 4가지뿐입니다.**

| # | 비활성 조건 |
|---|---|
| 1 | 날짜 입력값이 빈 문자열 |
| 2 | 금액 입력값이 (쉼표·공백 제거 후) 빈 문자열 |
| 3 | 카테고리 미선택 **또는** 등록된 카테고리가 0개 |
| 4 | `JR.ui.lock('save')` 로 잠긴 동안 (저장 처리 중) |

- 형식 위반·범위 위반(0원, 10억, 소수점, 2026-02-30, 1999년, 오늘+2년)은 **버튼이 활성**이며, 누르면 해당 I 슬롯 오류가 뜹니다.
- **사유**: 비활성 버튼은 이유를 말해주지 못합니다. 사용자가 "왜 저장이 안 되지"에서 멈춥니다. 값을 **비운 것**(아직 입력 안 함)과 값이 **틀린 것**(고칠 지점이 있음)은 다르게 다뤄야 합니다.

#### INT-03 · S-04 카테고리 `추가` · `확인` 버튼의 비활성 조건도 같은 원칙으로 축소

| 버튼 | 비활성 조건 (이것뿐) |
|---|---|
| `추가` | 입력값이 빈 문자열이거나 공백만 · 카테고리가 이미 20개 · `JR.ui.lock('category-add')` 잠금 중 |
| 편집 상태의 `확인` | 입력값이 빈 문자열이거나 공백만 · 잠금 중 |

- 12자 초과(E-115)·이름 중복(E-116)은 **버튼 활성** → 누르면 I 슬롯 오류. 자기 자신과 같은 이름으로 바꾸는 것은 중복이 아니며 성공 처리합니다(토스트 `카테고리 이름을 바꿨습니다`).
- 카테고리 20개 도달 시에는 입력란·`추가` 버튼을 비활성하고 안내문 `카테고리는 최대 20개까지 만들 수 있습니다.` 를 노출합니다(화면설계 그대로). 이때 E-117 은 두 번째 방어선입니다.

### 7-3. 문구 중복·자리표시자를 닫은 것

#### INT-04 · 카테고리 미선택 안내는 **E-112 문구 하나만** 씁니다

- **상황**: 화면설계 S-02 가 카테고리 영역에 안내 문구 `카테고리를 선택해 주세요.` 를 확정했는데, 구조설계 E-112(I, categoryId)의 문구가 **글자까지 동일**합니다. 같은 자리에 같은 문장이 두 출처에서 나옵니다(분배안 §5 경계 위반은 아니나 이중 정의).
- **확정**:
  - 문구의 단일 출처는 **`JR.err.MESSAGES['E-112']`** 입니다. 화면설계의 별도 안내 문구는 폐기합니다.
  - 표시 시점: **카테고리가 선택되지 않은 동안 상시** 표시(추가 모드 진입 직후 포함). 저장 시도 시 새로 띄우지 않습니다(이미 떠 있음).
  - 선택되는 순간 사라집니다(I 슬롯 규칙).
  - 이 문구를 "오류로 강조할지, 중립 안내로 보일지"는 **③ 디자인본부가 정합니다.** 문구와 표시 시점은 여기서 확정됐습니다.

#### INT-05 · 날짜 필드 안내 문구의 `(오늘로부터 1년 뒤)` 를 실제 날짜로 치환

  - `{max}` = `JR.model.maxDate()` 의 반환값을 그대로 삽입. 예: 2026-08-15 에 열면 `2000-01-01 ~ 2027-08-15 사이 날짜만 입력할 수 있습니다.`

#### INT-10 · 내보내기 대체 영역은 **성공했을 때도 노출**합니다 (구조설계 Q-012 확정)

- **상황**: `a.click()` 이 예외 없이 끝나도 브라우저가 다운로드를 조용히 차단했는지 자바스크립트가 알 수 없습니다(구조설계 §6-7 이 스스로 밝힌 사각지대). 화면설계는 "파일 저장이 막힌 경우에만" 대체 영역을 노출하도록 했으므로, 조용히 차단되면 **사용자는 성공 토스트만 보고 백업을 얻지 못합니다.**
- **확정**: `내보내기` 버튼을 누르면 `download()` 의 성공·실패와 **무관하게** 대체 영역을 노출합니다. 안내문만 2종으로 갈립니다.

| 상황 | 대체 영역 안내문 | 함께 뜨는 토스트 |
|---|---|---|
| 성공 (`method` = `anchor-blob` 또는 `anchor-data`) | **`파일을 저장했습니다. 저장된 파일이 보이지 않으면 아래 내용을 복사해 보관하세요.`** (② 파트장 신규 확정 문구) | `내보내기를 완료했습니다` |
| 실패 (`E-401`) | `파일 저장이 지원되지 않는 환경입니다. 아래 내용을 직접 복사해 보관하세요.` (화면설계 확정 문구 그대로) | `E-401` |

- 영역 구성은 화면설계 그대로: 안내문 + 읽기전용 텍스트 영역(JSON 전문) + `전체 선택` 버튼.
- 영역은 S-04 를 벗어나면 사라지고, 다시 `내보내기` 를 누르면 다시 나타납니다.
- 재료는 이미 확보되어 있습니다 — `JR.io.download()` 는 **성공 시에도 `data.text` 에 JSON 전문을 반환**합니다(구조설계 §6-7).
- **사유**: 잃는 것은 화면 한 칸이고, 얻는 것은 "백업했다고 믿었는데 파일이 없는" 사고의 차단입니다.

#### INT-12 · 초안 복원과 S-02 진입 규칙 (두 문서 모두 미정의)

구조설계 §6-6 은 초안을 언제 저장·폐기할지는 정했지만, **화면 어디에서 복원되는지**는 정해지지 않았습니다. 확정합니다.

1. **부팅 후 첫 화면은 항상 S-01 입니다.** 초안이 있어도 S-02 를 자동으로 열지 않습니다.
2. 초안 복원은 **S-02 진입 시점**에 `JR.model.loadDraft()` 로 1회 시도합니다.
3. 폼에 채우는 조건 — **아래를 모두 만족할 때만**:
   - `draft.mode` 가 이번 진입 모드(`'add'` / `'edit'`)와 같음
   - `mode === 'edit'` 이면 `draft.targetId` 가 이번에 여는 기록의 `id` 와 같음
   - `loadDraft()` 가 `data.code === null` 로 반환 (만료·대상 소실이 아님)
4. 조건을 만족하지 않으면 초안을 **조용히 버리고**(`clearDraft()`) 기본값으로 폼을 엽니다. 사용자에게 알리지 않습니다 — 그 초안은 지금 열려는 화면의 것이 아닙니다.
5. 복원되면 T 슬롯 `E-602`. 만료로 폐기되면 T 슬롯 `E-603` (S-02 진입 직후).
6. **복원된 상태는 "변경 있음"으로 간주합니다.** 이 상태에서 `취소` 또는 브라우저 뒤로 가기를 누르면 나가기 확인 대화상자가 뜹니다.

#### INT-13 · S-04 `가져오기` 버튼의 비활성 조건 추가

화면설계는 "처리 중"만 적었습니다. 여기에 추가합니다: **`FileReader` 또는 `input[type=file]` 미지원**(구조설계 §6-8-1 감지 결과). 이때 `E-002` 배너가 그 이유를 설명하고, 버튼은 **숨기지 않고 비활성**으로 둡니다(구조설계 §6-8-2 원칙). 버튼을 눌러 보려 한 경우의 두 번째 방어선은 `E-412` 입니다.

#### INT-14 · `index.html` 정적 요소 3개 (부팅 이전 상태의 구현 계약)

자바스크립트가 죽은 환경을 자바스크립트로 그릴 수 없으므로, 아래는 **HTML 에 미리 들어 있어야** 합니다.

| id / 태그 | 초기 내용 | 제거 시점 |
|---|---|---|
| `#jr-unsupported` | `이 브라우저에서는 앱을 사용할 수 없습니다. 크롬·엣지·사파리·파이어폭스의 최신 버전에서 열어 주세요.` (= E-001) | 부팅 필수 API 검사 통과 시 `boot.js` 가 DOM 에서 제거 |

배치·스타일은 ③ 디자인본부 영역입니다. **id 이름과 "부팅 성공 시 제거된다"는 규칙이 계약**입니다.

#### INT-15 · `JR.ui.show()` 는 권장이 아니라 **필수**입니다

구조설계 §5-8 은 슬롯 판정 헬퍼를 "두는 것을 권합니다"로 적었습니다. **권장을 확정으로 올립니다.** 모든 E-코드 표시는 `JR.ui.show(code, params, field)` 한 경로로만 나갑니다. `JR.ui.toast/inline/banner` 를 호출부에서 직접 부르지 않습니다(성공 문구 표시는 예외 — INT-16).

- 사유: 슬롯 판정이 호출부마다 흩어지면 E-코드 60개 × 호출 지점 수만큼 어긋날 자리가 생깁니다. ⑤ QA 가 "이 코드가 맞는 슬롯에 떴는가"를 한 곳에서 검증할 수 있어야 합니다.
- INT-01 로 S-02 에도 B 슬롯이 있으므로, 화면별 슬롯 대체 분기는 **필요 없습니다.** `show()` 는 화면을 알 필요가 없습니다.

#### INT-17 · 저장 실패 시 화면은 S-02 에 머뭅니다

화면설계는 "저장(성공) → S-01" 만 정의했습니다. **실패 시**: 화면 전환 없이 S-02 유지, `JR.ui.unlock('save')` 로 잠금 해제, 반환된 `code`(및 `data.errors` 가 있으면 필드별 전부)를 `JR.ui.show()` 로 표시. 입력값은 지우지 않습니다.

#### INT-19 · 목록에서 이미 사라진 기록을 열려고 할 때

기록 행을 눌렀는데 `JR.model.getExpense(id)` 가 `E-119` 를 반환하면(다른 탭에서 삭제된 경우): **S-02 로 진입하지 않고** S-01 에 머물며 T 슬롯 `E-119` (`이미 삭제된 기록입니다. 목록을 새로 불러왔습니다.`) 표시 후 목록을 다시 그립니다. 구조설계 §7-9 가 "목록에서 사라진 기록을 다시 열려고 할 때는 알린다"고 한 경로가 이것입니다.

#### INT-20 · 금액 입력란의 구현 계약

화면설계는 "숫자가 아닌 문자는 입력되는 순간 걸러진다 + 천 단위 쉼표 자동 표시"를 정했습니다. 구현이 갈릴 수 있는 3가지를 확정합니다.

| 항목 | 확정 |
|---|---|
| 입력 요소 | `<input type="text" inputmode="numeric" autocomplete="off">`. **`type="number"` 를 쓰지 않습니다** — 쉼표를 표시할 수 없고 브라우저마다 소수점·지수 입력을 허용합니다 |
| 필터 시점 | `input` 이벤트에서 `value.replace(/[^0-9]/g, '')` → 9자리 초과분은 자르지 않고 그대로 둠(E-104 가 저장 시 막음) → 천 단위 쉼표 재삽입. 붙여넣기도 같은 경로를 탑니다 |
| 커서 위치 | 쉼표 재삽입 후 커서를 **문자열 끝**으로 보냅니다. 중간 편집 시 커서 오프셋을 재계산하지 않습니다 — 순수 JS 로 정확히 맞추려면 분기가 늘고, 금액은 대개 끝에서 이어 칩니다 |
| 데이터 계층 전달 | UI 는 **쉼표가 붙은 원문 문자열을 그대로** `JR.model` 에 넘깁니다. UI 에서 미리 파싱하지 않습니다(파싱 규칙이 두 곳에 생기면 어긋납니다 — 구조설계 §5-4-3) |

이 필터 때문에 `E-102`(숫자 아님)·`E-105`(소수점)·`E-106`(숫자 변환 불가)은 **정상 조작으로는 도달하지 않는 두 번째 방어선**입니다. 삭제하지 마십시오 — 붙여넣기·IME·자동완성 경로가 필터를 우회할 수 있습니다.

#### INT-21 · 날짜 입력란의 구현 계약

| 항목 | 확정 |
|---|---|
| 입력 요소 | `<input type="date" min="2000-01-01" max="{maxDate()}">` |
| 미지원 브라우저 | 브라우저가 `text` 로 폴백합니다. 이때 방어선은 `E-107`(형식) → `E-109`(실재하지 않는 날짜) → `E-110`/`E-111`(범위) 순서입니다 |
| 데이터 계약 | 어느 경우에도 `JR.model` 에 넘기는 값은 `YYYY-MM-DD` 문자열입니다 |
| `min`/`max` 속성 | 신뢰하지 않습니다. 검증은 항상 `JR.model.validateExpense` 가 합니다 |

### 8-2. ④ 개발본부로 넘기는 실측 항목 13개 (구조설계 §9)

각 항목에 실측 방법과 결과별 분기가 이미 적혀 있어 **설계를 다시 하지 않고 그대로 구현할 수 있습니다.** 13개 중 12개는 이 설계의 폴백 경로 안에서 흡수됩니다.

> **단 하나의 예외 — 실측 #9 (`input[type=file]` + `FileReader` 가 `file://` 에서 동작하는가).**
> 이것이 실패하면 **F-08 의 절반(가져오기)이 동작하지 않습니다.** 이는 기능 범위 축소이므로 `tech-lead` 는 실측 즉시 `product-planner` 에 보고하고, `questions.md` 에 Q 를 남기십시오. ② 가 F-08 을 "내보내기 전용"으로 축소할지 판단합니다. **④ 가 혼자 결정하지 마십시오.**
> 실측 #6(localStorage 실제 상한)도 반드시 측정하십시오. `LIMIT_CHARS = 2500000` 은 추정치이며, 실측값이 이보다 **낮으면 반드시 낮춰야** 합니다.

## 9. 미결 사항 — 숨기지 않고 남깁니다

### 9-1. `tech-lead` 검토 **미수행**

`team-rules.md:28` 은 기획·설계 산출물의 검토자를 `tech-lead` 로 지정합니다. **2026-08-15 이 문서 작성 시점에 이 검토는 수행되지 않았습니다.** 서브에이전트가 다른 서브에이전트를 직접 호출할 수 없기 때문이며, 마스터가 별도로 붙입니다.

**이것이 승인의 전제인지에 대한 판정은 §10 에 있습니다. "검토받았다"고 쓰지 않았습니다.**

### 9-2. Q-002 · Q-003 — `strategy-lead` 답변 없음

`questions.md` 의 Q-002(B 차별점 24/25 의 표본 n=2)·Q-003(B 사용자 가치 24/30 의 세그먼트 괴리)은 **2026-08-15 현재 답변 없음**입니다.

**사이클 2 진행 영향: 없음.** 근거:

1. 두 질문의 `막힌 정도`는 처음부터 **"진행 가능"** 으로 기록되어 있습니다. ② 가 답변을 기다리는 구조가 아니라, 표현 방식으로 흡수하기로 하고 넘어온 건입니다.
2. 흡수 방법이 이 문서 **§1-1 에 실제로 이행되어** 있습니다 — C-1(표본 n=2 명시, 반례 Spent Pro 병기, "전부" 단정 금지) · C-2(리스크 부재 ↔ 가치 창출 분리 기술). 두 질문이 지적한 내용은 기획서 서술에서 이미 제거되었습니다.
3. 두 질문은 **점수 강도**의 문제이지 후보 적합성의 문제가 아닙니다. 답변이 "점수를 낮춰야 한다"로 오더라도 B 가 이 환경 제약(기술 제약 20/20)과 충돌하지 않는다는 사실은 변하지 않습니다.

**단, 아래는 사실대로 유지합니다** — 재채점 시 **B 82 · A 84 로 순위가 역전될 가능성이 실재**합니다(`기획-분배안.md` §1). 이 사실은 ⑥ 출시운영 산출물에서 "가장 좋은 아이디어로 검증되어 선정됨"처럼 기술하면 안 되는 근거가 됩니다. **선정은 유지하되, 선정 근거의 강도는 과장하지 않습니다.**

**Q-004 · Q-005 는 ② 결정으로 이미 정정 완료**되어 이 문서에 반영되었습니다(§1 형식 명칭·저장소 단일화·시각화 1종).
