### 6-1. 확인 불가 — 「통과」로 쓰지 않았습니다

| 항목 | 사유 |
|---|---|
| **Safari / WebKit 전 항목** | 시스템 라이브러리 부재로 **이번에도 기동 실패**(Y-2). INT-26 요구 4종 중 2종만 측정 |
| Chrome·Edge **정품 빌드** | Chromium 141 로 대신. 둘 다 Blink 이나 **동일하다고 단정하지 않습니다** |
| **실기 모바일** | `visibilitychange`·`pagehide` 는 **합성 이벤트로만** 검증. 실제 백그라운드 전환은 확인 불가 |
| 실제 다운로드 폴더 | Playwright 가 다운로드를 가로챕니다. **사용자 폴더에 실제로 떨어지는지는 확인 불가** |
| OS 파일 선택창 | `setInputFiles` 는 **합성 입력**. `FileReader` 판독은 진짜지만 선택창 경로는 확인 불가 |
| `env(safe-area-inset-*)` 실제 값 | 노치 기기 없음 |
| 실제 한글 시스템 폰트 렌더 | 컨테이너 폴백 폰트뿐 |
| **조용한 다운로드 차단 감지** | 방법 없음 — **Q-012 유지**(1차 호출과 동일 결론) |

### 6-2. ⚠️ 쓰기 경로 성능 — 1차 호출 수치가 **읽기 경로에만** 해당했습니다 (Y-4)

**파트장이 1차에 「16ms 를 어느 경우에도 넘지 않음」이라고 쓴 것은 읽기·계산 경로 기준이었습니다. 쓰기 경로는 그때 측정하지 않았고, 이번에 넘는 것을 확인했습니다. 기록을 정정합니다.**

**읽기 경로 — 매우 빠릅니다 (Chromium median/worst, ms)**

| 건수 | 목록 조회 | 통계(캐시 무효) | 통계(캐시 적중) |
|---|---|---|---|
| 1,000 | 0 / 0.1 | 0 / 0.1 | 0 / 0 |
| 5,000 | 0.1 / 0.2 | 0.1 / 0.3 | 0 / 0 |
| 5,000 단일월 | 0.8 / 1.5 | 0.9 / 1.3 | 0 / 0 |

**쓰기 경로 — 데이터 크기에 비례합니다 (Chromium 단일 호출 median/worst, ms)**

| 건수 | 직렬화 문자 | 월 이동 | 기록 저장 | 판정 |
|---|---|---|---|---|
| 100 | 10,781 | 0.3 / 0.6 | 0.6 / 1.1 | ✅ |
| 500 | 54,781 | 1.1 / 1.7 | 1.3 / 2 | ✅ |
| **1,000** | 109,881 | **2.1 / 3** | **1.8 / 2.4** | ✅ **설계 목표 기준선** |
| 2,000 | 222,881 | 3.5 / 5.5 | 4.2 / 5.8 | ✅ |
| **5,000** | 561,881 | **12.3 / 16.5** | **16 / 24.9** | ⚠️ **16ms 초과** |

- **원인**: `setSelectedMonth` 는 설정 한 값만 바꾸는데도 `persist()` → `writeAll()` 이 **expenses 전체를 `JSON.stringify` 하고 `.bak` 사본까지 씁니다.** 5,000건이면 한 번의 월 이동이 약 560KB × 수 회의 직렬화/저장을 유발합니다.
- **저장소가 이미 채워진 상태에서는 더 나빠집니다** — 복구 사다리와 `usage()` 키 스캔이 겹쳐 **월 이동 median 50~115ms** 를 관측한 조건이 있습니다(`perf2.cjs`). **단정하지 않고 그대로 보고합니다.**
- **④ 판단 — 반려하지 않았습니다**: ⓐ **설계 목표(1,000건)에서는 5~8배 여유**로 통과합니다. ⓑ 구조설계 §4-4 가 **「미리 최적화하지 않습니다」**로 못박았습니다. ⓒ 이 원자적 쓰기 순서(expenses→categories→settings + `.bak`)는 **§6-2 복구 사다리와 §6-3 손상 격리가 의존하는 설계**여서, 설정만 따로 쓰도록 쪼개면 **예외 2·3번(용량 초과·JSON 손상)의 보증이 흔들립니다.** 증상보다 위험한 수술입니다.
- **⑤ 에게**: 이것은 **결함 티켓이 아니라 알려진 제한사항**입니다. 성능 항목을 볼 때 **1,000건 기준으로 판정**하시고, 5,000건 수치는 상단 밖 참고로 읽어 주십시오. **정식 최적화가 필요하다는 판정은 ② 소관**입니다.

## 7. ⑤ 품질본부에 드리는 말

1. **콘솔 에러 0건은 실제로 눈으로 확인했습니다** — 2엔진 종합 스윕 + 개별 시나리오 20여 건, 전부 0.
2. **예외 8종은 「구현되어 있다」가 아니라 「실제로 잡히는 것을 봤다」입니다.** 저장소를 차단하고, 용량을 넘기고, JSON 을 깨뜨리고, 남의 파일을 넣고, 3연타하고, 새로고침하고, 다운로드를 막고, API 를 지웠습니다.
3. **§5-3(비-`{ok}` 17개)과 §5-7(UI 도달 불가 E-코드 3개)을 먼저 읽어 주십시오.** 이 두 가지를 모르면 **없는 결함 8건**을 만들게 되고, ④↔⑤ 왕복 3회 한도를 헛되이 씁니다.
4. **④↔⑤ 반복은 최대 3회**입니다. 초과하면 중단하고 사용자에게 보고합니다.
5. **QA 결과는 ④ 파트장이 검토합니다**(상호 검토 규정). 되돌릴 것이 있으면 **무엇을 누가 고쳐야 하는지** 적어 주십시오 — ④ 가 `frontend-dev`/`fullstack-dev` 중 소유자에게 배정합니다.
6. **Y-1 을 잊지 마십시오** — `product-planner` 교차검토는 **아직 수행되지 않았습니다.**
