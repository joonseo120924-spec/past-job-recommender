## D-023 상세 — 슈퍼베이스 연동

**지시 원문 (2026-08-29)**: "지금 만든 팀을 슈퍼베이스와 연동해줘"

**무엇을 넣는가**: 팀 **상태**입니다. 사용자 확인을 거쳐 「팀 상태 동기화」로 확정했습니다.
가계부 앱의 백엔드로 쓰는 것은 **채택하지 않았습니다** — ② 구조설계 1,448행이 이미 `localStorage` 단일·외부 네트워크 요청 0건을 전제로 확정돼 있어, 그러려면 ② 로 되돌려 재설계해야 합니다.

**구조**
| | 역할 | 정본 |
|---|---|---|
| 저장소 `ai-team/` | 실제 상태 | ✅ |
| 슈퍼베이스 | 팀이 읽는 상태 (어느 대화창에서도 즉시 조회) | 사본 |
| 노션 작업 일지 | 사람이 읽는 기록 | 사본 |

**근거**: 08-10~08-15 로컬/원격 6일 분기, 08-15~08-29 13일 공백 — 두 사고 모두 "새 대화창이 붙는 순간 자동으로 읽히는 상태 저장소가 없다"는 같은 뿌리입니다. 저장소는 커밋해야 보이고 노션은 사람이 열어야 보입니다.

**안전 설계**
- `team_events`·`team_state` 에 **삭제 정책을 주지 않았습니다** — publishable 키로 기록을 지울 수 없습니다

- 이 저장소는 **공개**이므로 키는 `ai-team/supabase/.env` (gitignore) 에만 둡니다

**검증 완료 (2026-08-29 실측)**: 사용자가 `schema.sql` 을 실행한 뒤 왕복으로 확인했습니다 — `push` 8/8 → `status` 8/8 일치 → `pull` 차이 0 → `event` 기록 → 뷰 `team_now` 조회 정상.
기록 삭제 방어도 실측했습니다: `DELETE /team_events` 는 **HTTP 204 를 돌려주지만 실제 삭제 0건**입니다 (delete 정책이 없어 RLS 가 대상 행을 안 보여줌). **204 를 성공으로 읽으면 안 됩니다.**
**여전히 미검증**: `supabase-sync.ps1` 실행 — 이 컨테이너에 PowerShell 이 없습니다.

**`.claude/` 수정 아님**: 전부 `ai-team/` 아래이므로 RED 예외 요건 검토 대상이 아닙니다.
